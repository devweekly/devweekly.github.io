## 二、仍未完成或需要真实环境验收的事项

### P0：需要真实语料和模型运行，不能靠单元测试宣称完成

1. **真实作品的时点分析质量验收**
   - 在实际原著上从中间章节创建宇宙，执行完整八步知识构建。
   - 抽样核对人物小传、关系变化、主线归属、伏笔状态、MacGuffin、故事核心、卷级弧线和逐章人物状态。
   - 重点检查模型是否把推断写成事实、是否错误合并人物/关系、是否漏掉重要伏笔。
   - 需要原著语料和可用模型配置；当前仓库 CI 没有这些输入，不能伪称已验收。

2. **真实模型生成的语义泄漏对抗测试**
   - 自动测试已覆盖 bounded 检索、分析上下文、Corpus Craft、Writing Brief 和最终公共章节 Prompt 的未来剧情 marker。
   - 仍需真实模型运行，使用父宇宙未来独有的人物、事件、对白和结局作为 canary，检查模型是否通过用户 brief、上下文拼接或模型既有知识自行补入未来剧情。
   - 这属于模型行为验收，不是再加一条字符串断言就能证明安全。

3. **文学质量评估**
   - 使用真实章节评估风格趋势报告是否能区分场景差异与风格漂移，人物弧光提示是否有创意而不僵化。
   - 不应以相似度、句长、段落长度或固定人物标签作为自动 gate；文学性、文笔、艺术风格优先。

### P1：产品能力仍有明确边界

4. **默认语义检索尚未开箱即用**
   - BM25 是可靠默认路径；Vane 是可选混合检索，已经接入普通/长章节召回，并采用 staging 索引构建与发布。
   - 原生包未安装时，后台知识构建将 Vane 标记为 skipped；真正向量语义检索依赖安装 Vane、配置 embedding endpoint/model/dimension。缺配置时使用 text-only，稳定占位向量不代表语义检索。
   - 后续可补配置诊断和向量连通性检查，但不能把未配置状态误报为语义检索可用。

5. **检索与风格的长期基准治理**
   - BM25/Vane 检索评测 runner、Recall@5/MRR@10/nDCG@10 指标和数据集模板已实现；尚无针对真实原著的人工 gold query/chunk labels，因此还不能判断 Vane 是否优于 BM25。
   - Style Regression 已有逐章报告和每五份报告触发的趋势观察；尚无基准样本集版本治理、场景类型分层基线和长期可视化比较。二者都属于评估/创作辅助，不应变成阻断写作的质量门禁。

### P2：有意延后的架构增强

6. **多进程/多实例协调**
   - 当前 queue/mutation lock 只覆盖单个 Workbench 进程。单机单实例可接受；多进程部署前需增加 SQLite/文件锁或其他跨进程协调。

7. **章节内段落级分叉**
   - 当前正式起点粒度为章节级。段落/字符偏移需要位置模型、前文切分和 Story State 还原规则，不能仅改 UI。

8. **Story Arc / Chapter Plan 规范化**
   - 当前仍以文件快照为主。只有在需要结构化查询、差异比较和复杂回滚时，再考虑 SQLite 规范化。

9. **Source Canon 的完整物理共享**
   - original.txt 已优先 reflink，保持独立 inode；不支持时复制回退。
   - bounded library 和 SQLite 快照仍独立存储，这是历史时点隔离的必要代价。跨宇宙共享不可变章节对象/索引属于后续存储优化，不是当前正确性缺陷。

10. **无限自动连载**
    - 当前按次生成章节是有意设计，不默认无人监督无限循环。可选批量任务应具备停止、失败恢复和状态提交边界。

## 三、当前验收结论

当前可以确认：核心章节创作闭环、Story Universe 生命周期、历史章节 Fork、时点安全的检索/数据库/分析上下文、八步异步知识构建、人物跨章弧光 Planner 提示、Style Regression 趋势观察、单进程并发协调和 copy-on-write 原文优化均已有实现与相应自动化测试。

不能据此宣称：模型对真实原著的分析一定准确、真实模型绝不会产生语义级未来剧情泄漏、或风格趋势能客观衡量文学质量。这些必须在真实语料和实际模型上验收。

最近代码提交 e5b0fe2a2d3a9a094db0d527c30df24f90802760 的 GitHub Actions run 42370742583 已通过 npm ci、npm run typecheck、npm test、npm run build；覆盖时点资料原子发布、Corpus Craft 世界细节导出与覆盖状态、bounded sourceHash 校验、Vane 索引 staging/回滚和可选 Vane 跳过逻辑。之后的提交为文档更新；仍以最新 main 对应的 Actions run 为准。

## 2026-11-07 后续实现记录（三）：宇宙知识重建后台任务

新增 Workbench 知识构建 API：

- `POST /api/worlds/:worldId/knowledge-build`：为独立故事宇宙异步启动知识重建，HTTP 202 立即返回，不阻塞写作。
- `GET /api/worlds/:worldId/knowledge-build`：读取当前构建状态、步骤、时间、退出码、stdout/stderr 摘要。
- 按顺序复用现有 CLI：`analyze-story`、`analyze-profiles`、`analyze-character-states`、`analyze-corpus-craft`、`vane-index`。所有步骤都以当前宇宙 ID 运行，CLI 通过该宇宙自己的 worldDir 和 bounded library 读取资料；不会复制父宇宙的派生索引。

## 2026-11-07 后续实现记录（四）：修复历史分析缺失的章节目录

进一步沿后台分析调用链检查后发现一个此前遗漏的阻断问题：`analyze-story` 和 `analyze-corpus-craft` 不只读取 universe-local `library/index.json`，还必须读取 `analysis/<worldId>/chapter-index.json`。历史宇宙复制策略会排除整个 `analysis` 目录，因此即使 bounded library 和 SQLite 已准备好，后台分析仍会因缺少 chapter catalog 而失败。

已修复：

- Create 和 Fork 在构建 bounded library 后，从原文章节目录生成宇宙自己的 `analysis/<universeId>/chapter-index.json`。
- 目录只保留 bounded library 中出现的章节，并且只写入分析所需的章节编号、标题、卷号和行号字段；不复制来源目录中的其他未来章节元数据、摘要或未知字段。
- Fork 同样按原文起点重新生成，不继承父宇宙的分析目录。
- 创建/分叉 staging 失败时，同时清理已写出的宇宙专属分析目录，避免残留孤立目录。
- Create API 集成测试补充了 catalog fixture 和断言，验证第三章及其未来标记不会进入新宇宙 catalog。

这是重要修复：之前新增的后台知识重建 API 虽然已接入现有 CLI，但没有 bounded catalog 时无法完成故事分析与 Corpus Craft。现在 Create/Fork 会为后续重建准备必要的、时点受限的章节目录。

仍需 CI 验证 TypeScript 类型、测试与构建；当前工具未提供可核实的 workflow run 结果。

- **最终章节 Prompt 层测试**：把写作流水线实际使用的公共章节上下文抽为 `buildCommonWritingContext`，`writeChapter` 本身使用该函数。测试核验最终公共 Prompt 的组成包含 bounded 背景、检索证据、分析参考、起点正文和文学性优先指令；同时不含未来剧情 marker。它与 Create API 的真实检索、SQLite、Corpus Craft、Writing Brief 隔离测试共同覆盖检索到 Prompt 的主要上下文层，但仍不能替代真实模型输出的语义泄漏抽样。
- **风格趋势长期计数修复**：过去将采集窗口限制为 1000 份报告后，用窗口长度判断每五份触发，会在报告数达到上限后每章重复触发。现将完整历史计数与送入模型的最近 30 份上下文分离；即使超过 1000 份，仍按总报告数每五份触发一次。新增 1005 份报告测试。
- **竞态与回滚测试**：增加同一宇宙并发 Fork/Archive 的 API 竞态测试，验证 per-world queue 保证只可能先完成 fork 再归档，或先归档再拒绝 fork；另有 Create staging 中途失败的故障注入，验证无残留 staging/半成品目录。该测试覆盖的是单进程并发边界，不等于多进程压力测试。
- **ADR 状态校正**：ADR-0005 增补实际实现状态与边界，明确当前起点为章节级，不支持段落内偏移；source-canon.json 只记录来源身份，宇宙检索必须使用本地 bounded index；reflink 仅为可选物理优化，失败时普通复制。
- **文学质量验收边界**：当前代码与自动测试能证明时点输入范围、资料导出来源和 Prompt 组成；不能仅凭 CI 证明人物弧光分析是否准确、伏笔判断是否合理、文风趋势是否对文学表达有帮助。这部分需要实际作品语料和真实模型执行，不能通过硬阈值替代。

## 2026-11-07 补充：时点资料目录原子发布

- 复核 `exportAsOfDossier` 后发现，原实现逐个 rename 七份 Markdown；进程若在中途崩溃，目录可能混合新旧版本。现改为先在宇宙目录内构建完整 staging 目录，再切换发布目录；切换失败会尝试恢复上一版，旧目录清理失败不会破坏已发布版本。
- 新增真实 SQLite + 文件系统测试，验证导出完整文件集合、旧版多余文件被清除、内容正确且不遗留 staging/backup 文件。
- 本修复的目录切换包含“旧目录移至 backup、新目录 rename 到目标”的短暂切换窗口；对当前单进程 per-world 知识构建足够，但不宣称跨进程读者的无缝原子交换。多进程部署仍需目录版本指针或文件锁。

## 2026-11-07 补充：Vane 索引重建的失败隔离

- Vane 原先在活动索引目录上删除旧 ID 并写入新文档；embedding 或批量写入中途失败时，存在活动索引不完整的风险。
- 现改为独立 staging 目录构建、flush 并写入 manifest，关闭 Vane DB 后再切换活动目录；切换失败恢复旧目录。旧索引不会在新索引构建完成前被修改。
- 增加成功切换与切换失败回滚的文件系统测试。Vane 原生模块的真实 macOS 运行、embedding provider 和检索质量评测仍未由通用 CI 证明。

## 2026-11-07 补充：派生语料缓存必须匹配当前 bounded source

- 复核历史分支时点隔离时发现，仅检查 Corpus Craft 文件的 worldId 不够：同一 worldId 下也可能残留旧语料分析缓存。现有写作上下文、Vane 重建和 as-of 世界细节导出均要求 Corpus Craft 的 sourceHash 与当前 bounded chapter unit 精确匹配；无法建立 bounded chapter catalog 时，不注入/不索引派生素材。
- 增加 Create API 集成回归：人为在子宇宙写入 worldId 正确但 sourceHash 错误、包含未来 marker 的 Corpus Craft 文件，实际 buildCorpusCraftContext 不得召回。
- as-of 世界细节导出现在同样校验 chapterId + sourceHash，并在测试中用真实 bounded chapter units 构造有效 fixture。这样避免 stale same-world cache 绕过只检查 worldId 的隔离策略。
