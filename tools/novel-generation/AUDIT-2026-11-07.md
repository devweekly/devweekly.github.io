# Novel Generation 完整功能审计（2026-11-07）

## 审计范围与结论

本次按 GitHub `main` 当前代码检查了 `src/` 核心模块、CLI 命令、Express API、React Workbench、SQLite schema、自动化测试、README、ARCHITECTURE、ADR 0004/0005 和 GitHub Actions 工作流。重点覆盖小说生成闭环、人物/情节知识、风格回归、人物沙盘、独立故事宇宙、章节分叉、时点隔离、运行恢复和测试。

**结论：核心单章创作闭环已具备，主要功能不是“还没做”，而是仍有几项明确的产品/工程闭环缺口。当前不应宣称整个项目已完整交付。** 本报告区分“代码缺失”“已实现但缺端到端验证”“明确暂缓的增强项”，避免把可选能力误报为未完成。

### P1：功能可用，但缺少完整产品闭环

5. **按起点重新生成历史人物/情节聚合**
   - 目前为避免未来剧情泄漏，`story_analysis`、全书人物画像、主线/伏笔聚合、卷级摘要、实体注册、annotations 等全书级聚合被保守清空。
   - 这保证“不看见未来”，但也意味着新宇宙无法直接使用起点之前已经分析出的完整人物小传、主线、伏笔和故事核心。
   - 应新增按章节截止点的历史分析重建能力：只用起点及以前证据，生成该宇宙自己的 as-of 人物/剧情聚合快照。不能把原文末尾的全书分析直接复制回来。
   - 重建应为可选增强，不应成为创建宇宙和开始写作的硬门槛。

6. **Universe 的原文资料与设定文件隔离**
   - 已在 create 和 fork 两条复制路径中实施 fail-closed 文件策略：排除 analysis、Corpus Craft、Vane、Style Reference 派生目录，以及 world-bible、characters、timeline、fruit-worlds、yanfu-system、style-profile 等根级全书汇总文件。
   - 这些资料尚未按起点重建，因此历史宇宙可能暂时缺少部分整理后的背景设定；这是有意的安全取舍，不能回退为复制全书总结。
   - 剩余工作是补文件系统/API E2E 测试，并实现基于起点之前证据的 as-of 设定重建。

7. **Vane 与 Corpus Craft 的宇宙构建自动化**
   - 当前 Vane 是可选能力，需要显式执行 `vane-index`；Corpus Craft 需要显式执行 `analyze-corpus-craft`。
   - 新宇宙创建后不会自动完成这两种索引/素材分析。可以继续保持可选、后台运行，但应提供“缺失检测 + 一键/自动后台构建 + 进度/失败状态”，而不是让用户自行记忆 CLI 命令。
   - Vane 无 embedding 配置时只能使用文本检索；语义检索依赖外部 embedding endpoint 和模型配置，当前不是开箱即用能力。

8. **Source Canon 物理共享与存储去重**
   - 当前采用宇宙独立目录/副本加截断索引，逻辑上隔离，物理上仍复制数据库和资料。
   - 真正只读共享的 Source Canon 数据库/索引、宇宙本地派生数据分层尚未完成。
   - 这属于存储优化，不应优先于时点隔离正确性和集成测试。

9. **Story Arc / Chapter Plan 数据规范化**
   - Story Arc 当前主要以 Markdown 快照维护；ARCHITECTURE 已明确尚未将 Arc/Chapter/Scene 计划规范化为 SQLite 多表和显式版本迁移。
   - 当前功能可用，不是阻断续写；未来如需跨宇宙查询、计划差异、复杂回滚和结构化 UI，再做数据库规范化。

10. **Style Regression 的长期基准管理**
    - 每章自动生成风格回归观察报告已经实现，不是缺失功能。
    - 尚缺：样本版本与章节版本的长期关联、跨章节批量趋势报告、基准集治理、风格变化可视化。
    - CI 风格门禁不建议默认引入；若未来增加，只能作为非阻断提示，不能用相似度/句长统计判定文学质量。

11. **人物弧光的跨章分析与创作反馈**
    - 已有人物逐章状态、长期画像、arcMilestones 和人物时间线 UI。
    - 尚未形成“自动汇总多章弧光变化 → 识别反复/转向/反差/代价 → 给 Planner 创意提示”的完整反馈视图。
    - 不应把它做成角色一致性硬约束；人物可以突变、反复、由白转黑或由黑转白，系统只提供材料和可能性。

### P2：明确可延后，不应阻断当前使用

12. **语义检索**
    - 当前基础检索是本地 BM25 风格词项检索；复杂别名、隐喻、跨段落指代和语义相似场景可能漏检。
    - Vane 混合检索有可选路径，但依赖额外 binding/embedding 配置，不等同于默认语义检索已交付。

13. **跨进程/多实例锁**
    - 当前队列和 mutation lock 只在单个 Workbench 进程内有效。
    - 若未来运行多个进程/多实例，需要数据库锁或跨进程协调。当前单机单实例场景可接受。

14. **无限自动连载**
    - 当前每次明确触发生成一章，不默认无人监督无限循环。
    - 这是有意设计，不属于缺陷；未来可提供可停止的批量续写任务，但不能牺牲状态提交和失败恢复。

15. **任意章节内段落级起点**
    - 当前宇宙从原文章节起点开始，不支持章节内具体段落/字符偏移作为正式分支起点。
    - ADR 已提出可选段落级位置，但第一版 UI/API 尚未实现。

## 五、验收判断

当前可以说“普通/长章节自动创作闭环、人物/故事图谱基础、风格观察、人物推演沙盘、独立宇宙和章节分叉第一版已实现”。

本轮已对 create 与 fork 的文件复制路径增加 fail-closed 过滤，并同步架构与 README。仍未取得可核实的最新 GitHub Actions workflow 结果，也未在本地执行 typecheck/test/build；SQLite 集成测试与 API/FS E2E 仍未完成，因此不能宣称历史起点隔离已通过完整验收。

## 2026-11-07 后续实现记录（三）：宇宙知识重建后台任务

新增 Workbench 知识构建 API：

- `POST /api/worlds/:worldId/knowledge-build`：为独立故事宇宙异步启动知识重建，HTTP 202 立即返回，不阻塞写作。
- `GET /api/worlds/:worldId/knowledge-build`：读取当前构建状态、步骤、时间、退出码、stdout/stderr 摘要。
- 按顺序复用现有 CLI：`analyze-story`、`analyze-profiles`、`analyze-character-states`、`analyze-corpus-craft`、`vane-index`。所有步骤都以当前宇宙 ID 运行，CLI 通过该宇宙自己的 worldDir 和 bounded library 读取资料；不会复制父宇宙的派生索引。
- 每一步状态落盘到 `.output/<world>/workbench/knowledge-build.json`；服务重启后将未完成任务标记失败，可重新发起，不会显示永久 running。
- 某一步失败不会中断后续步骤，最终状态区分 completed、partial、failed。Vane 未安装或 embedding 配置异常会明确记录为失败，不伪装成语义检索已可用。
- 该 API 目前是显式启动入口，尚未自动挂到新建/分叉完成事件，也尚未接入 Workbench 前端按钮/状态面板；因此“后台任务能力已实现”，但“创建宇宙后自动构建、UI 一键触发”仍未完成。

## 2026-11-07 后续实现记录（四）：修复历史分析缺失的章节目录
