# Novel Generation 完整功能审计（2026-11-07）

## 审计范围与结论

本次按 GitHub `main` 当前代码检查了 `src/` 核心模块、CLI 命令、Express API、React Workbench、SQLite schema、自动化测试、README、ARCHITECTURE、ADR 0004/0005 和 GitHub Actions 工作流。重点覆盖小说生成闭环、人物/情节知识、风格回归、人物沙盘、独立故事宇宙、章节分叉、时点隔离、运行恢复和测试。

**结论：核心单章创作闭环已具备，主要功能不是“还没做”，而是仍有几项明确的产品/工程闭环缺口。当前不应宣称整个项目已完整交付。** 本报告区分“代码缺失”“已实现但缺端到端验证”“明确暂缓的增强项”，避免把可选能力误报为未完成。

## 二、仍未完成或尚未闭环的功能

### P0：必须完成，关系到正确性和可交付性

1. **原文知识库时点快照的 SQLite 集成测试**
   - 目前 `restrictKnowledgeDatabaseToEntry` 位于 server 路由模块内部，没有针对真实 schema 的隔离测试。
   - 必须验证：起点前/起点/起点后章节目录；beats、relations、人物逐章状态；mentions 通过 chapter_id 过滤；全书聚合表清空；未知表清空；缺字段整表清空；起点不存在时删除副本；过滤异常时 staging 不残留未过滤 DB。
   - 必须覆盖新建宇宙和从旧宇宙分叉两条路径。
   - 验收不是“函数返回成功”，而是实际查询子宇宙 DB 和检索结果，确认不存在起点之后的证据。

2. **原文时点隔离的端到端测试**
   - 测试从中间章节创建宇宙，生成检索上下文不得出现后续章节专属人物状态、事件、对白、伏笔或素材。
   - 测试从父宇宙历史章节分叉，子宇宙恢复该章时点状态，且不能继承父宇宙分叉点之后的任何内容。
   - 检查 CLI 的所有数据入口，而不只是主 library：novel.db、Corpus Craft、Vane、world bible/characters/timeline 等文件、style references、Story Analysis Context。
   - 目前代码采用本地截断索引和保守 DB 清理，但缺少上述端到端证明。

3. **Story Universe 数据隔离回归测试**
   - 当前 `universe-branch.test.ts` 主要覆盖纯函数：状态 identity 重绑定、路径重映射、起点前情预算。
   - 缺少 API/文件系统/SQLite 集成测试：新建、切换、归档/恢复、分叉、归档期间启动生成、生成启动期间归档、两个宇宙并发操作、失败回滚、服务重启恢复。
   - ADR 0005 也明确提出为派生知识表、状态表、图谱和运行记录补充隔离测试；尚未完成。

4. **自动化测试与 CI 结果确认**
   - 仓库已有 `.github/workflows/novel-generation.yml`，执行 `npm ci`、typecheck、test、build。
   - 本次审计未取得可核实的最新 workflow run 结果；GitHub commit combined status 返回空 statuses，不能据此声称 CI 通过。
   - 最近的代码改动需要真实执行 workflow，处理失败后再验收。

### P1：功能可用，但缺少完整产品闭环

5. **按起点重新生成历史人物/情节聚合**
   - 目前为避免未来剧情泄漏，`story_analysis`、全书人物画像、主线/伏笔聚合、卷级摘要、实体注册、annotations 等全书级聚合被保守清空。
   - 这保证“不看见未来”，但也意味着新宇宙无法直接使用起点之前已经分析出的完整人物小传、主线、伏笔和故事核心。
   - 应新增按章节截止点的历史分析重建能力：只用起点及以前证据，生成该宇宙自己的 as-of 人物/剧情聚合快照。不能把原文末尾的全书分析直接复制回来。
   - 重建应为可选增强，不应成为创建宇宙和开始写作的硬门槛。

6. **Universe 的原文资料与设定文件隔离审查**
   - 当前新宇宙会复制源 world 的资料文件，再生成自己的截断 library；Vane 索引排除，Corpus Craft 按宇宙目录独立。
   - 需要逐项确认被复制的 `world-bible.md`、`characters.md`、`timeline.md`、`fruit-worlds.md`、`yanfu-system.md`、`style-profile.md` 和 style references 是否包含起点之后的信息。
   - 如果这些文件是基于全书生成的总结，它们可能成为绕过 DB/library 截断的未来剧情泄漏通道。应为文件建立来源/时点元数据；不能证明时点安全的聚合文件应排除或重建。
   - 这是时点隔离的高优先级剩余风险，不能只检查 SQLite。

7. **Vane 与 Corpus Craft 的宇宙构建自动化**
   - 当前 Vane 是可选能力，需要显式执行 `vane-index`；Corpus Craft 需要显式执行 `analyze-corpus-craft`。
   - 新宇宙创建后不会自动完成这两种索引/素材分析。可以继续保持可选、后台运行，但应提供“缺失检测 + 一键/自动后台构建 + 进度/失败状态”，而不是让用户自行记忆 CLI 命令。
   - Vane 无 embedding 配置时只能使用文本检索；语义检索依赖外部 embedding endpoint 和模型配置，当前不是开箱即用能力。

8. **Source Canon 物理共享与存储去重**
   - 当前采用宇宙独立目录/副本加截断索引，逻辑上隔离，物理上仍复制数据库和资料。
   - 真正只读共享的 Source Canon 数据库/索引、宇宙本地派生数据分层尚未完成。
   - 这属于存储优化，不应优先于时点隔离正确性和集成测试。

9. **Story Arc / Chapter Plan 数据规范化**
   - Story Arc 当前主要以 Markdown 快照维护；ARCHITECTURE 已明确尚未将 Arc/Chapter/Scene 计划规范化为 SQLite 多表和显式版本迁移。
   - 当前功能可用，不是阻断续写；未来如需跨宇宙查询、计划差异、复杂回滚和结构化 UI，再做数据库规范化。

10. **Style Regression 的长期基准管理**
    - 每章自动生成风格回归观察报告已经实现，不是缺失功能。
    - 尚缺：样本版本与章节版本的长期关联、跨章节批量趋势报告、基准集治理、风格变化可视化。
    - CI 风格门禁不建议默认引入；若未来增加，只能作为非阻断提示，不能用相似度/句长统计判定文学质量。

11. **人物弧光的跨章分析与创作反馈**
    - 已有人物逐章状态、长期画像、arcMilestones 和人物时间线 UI。
    - 尚未形成“自动汇总多章弧光变化 → 识别反复/转向/反差/代价 → 给 Planner 创意提示”的完整反馈视图。
    - 不应把它做成角色一致性硬约束；人物可以突变、反复、由白转黑或由黑转白，系统只提供材料和可能性。

### P2：明确可延后，不应阻断当前使用

12. **语义检索**
    - 当前基础检索是本地 BM25 风格词项检索；复杂别名、隐喻、跨段落指代和语义相似场景可能漏检。
    - Vane 混合检索有可选路径，但依赖额外 binding/embedding 配置，不等同于默认语义检索已交付。

13. **跨进程/多实例锁**
    - 当前队列和 mutation lock 只在单个 Workbench 进程内有效。
    - 若未来运行多个进程/多实例，需要数据库锁或跨进程协调。当前单机单实例场景可接受。

14. **无限自动连载**
    - 当前每次明确触发生成一章，不默认无人监督无限循环。
    - 这是有意设计，不属于缺陷；未来可提供可停止的批量续写任务，但不能牺牲状态提交和失败恢复。

15. **任意章节内段落级起点**
    - 当前宇宙从原文章节起点开始，不支持章节内具体段落/字符偏移作为正式分支起点。
    - ADR 已提出可选段落级位置，但第一版 UI/API 尚未实现。

## 三、文档与实现不一致（需要修正文档）

1. ARCHITECTURE 第 1.1 节仍写“宇宙归档/删除管理尚未实现”，但当前 server API 和 ChapterStudio UI 已支持归档/恢复；没有物理删除入口是有意设计，不是缺失。
2. ARCHITECTURE 第 1.1 节仍写“原文 library 通过 source-canon.json 共享读取、不再复制索引”，但当前创建宇宙流程会生成 universe-local bounded `library/index.json`；CLI 对本地截断索引缺失会 fail closed。文档描述已过期。
3. ARCHITECTURE 其他段落对 Source Canon 共享、Vane/Corpus Craft 旁路隔离的表述需要统一成当前真实实现：原文来源 ID 指针 + 本地截断索引/数据库副本，而非完整的物理共享只读库。
4. README 的历史说明与当前 Workbench 的 Story Universe、人物时间线、分支树和归档功能应补齐，避免用户只看到旧 CLI 工作流。
5. ADR 0005 的“后续阶段”仍包含已实现的归档/分支树等条目，需要标注完成状态；原文共享库和外键隔离测试则仍未完成。

## 四、建议交付顺序

1. **先做 P0 测试**：抽离时点快照过滤模块，补真实 SQLite schema 测试和新建/分叉集成测试。
2. **再做 P0 端到端泄漏审计**：特别检查复制的 world bible、人物、时间线、风格资料，以及 Corpus Craft/Vane 等数据入口。
3. **补 P1 历史分析重建**：为宇宙起点构建只基于截至起点证据的角色、主线、伏笔、故事核心快照。
4. **补 P1 后台能力构建**：新宇宙可选自动生成 Corpus Craft/Vane 索引，并在 UI 显示状态。
5. **统一文档与 UI 说明**：修复 ARCHITECTURE/ADR/README 过期描述。
6. **最后考虑 P2**：语义检索、长期风格趋势、Arc 规范化、段落级起点和跨进程锁。

## 五、验收判断

当前可以说“普通/长章节自动创作闭环、人物/故事图谱基础、风格观察、人物推演沙盘、独立宇宙和章节分叉第一版已实现”。

当前不能说“任意起点的原著知识已经完整、安全地按时点隔离并经端到端验证”，也不能说“所有宇宙派生数据都已完成外键级隔离测试”。这两项是当前最重要的工程缺口。

本次检查没有在 GitHub Actions 中取得可核实的最新 workflow 运行结果，也没有在本地执行 typecheck/test/build；报告不把静态代码检查伪装成测试通过。
