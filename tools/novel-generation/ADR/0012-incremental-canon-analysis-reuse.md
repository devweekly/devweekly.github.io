# ADR 0012：原著分析缓存与历史宇宙复用

- 状态：已采纳
- 日期：2026-11-11

## 背景

原著分析是跨故事宇宙共享的长期资产。旧实现把模型、Prompt、批次布局和整本语料哈希合并成一个缓存目录指纹；任意章节变化都会使所有批次失去命中机会。新建历史故事宇宙时，旧实现只复用完全落在入口章节之前的整批缓存；入口章节落在批次中间时直接返回失败。随后，合并快照的严格时点过滤会丢弃跨越入口的聚合记录并标记不完整，知识构建便在子宇宙再次执行整本（有界）原文分析。

此外，旧版 `--delta` 通过“批次数相同、取最近修改目录”选择旧缓存，可能选中另一份语料；`--delta --merge-only` 的执行路径也曾在合并前触发模型调用。

## 决策

1. **缓存身份与批次内容分离。** 缓存目录由数据分析协议版本、Prompt 版本、模型和 `maxChars` 确定；每个批次通过独立 manifest 记录章节 ID、章节正文哈希及批次指纹。某一批内容变化只使该批失效，不影响其他批次。
2. **兼容旧缓存必须精确。** 旧版整书哈希缓存只允许在完整语料、模型、Prompt 和批次布局精确匹配时迁移。禁止仅凭目录修改时间或批次数量选缓存。旧 delta 批次可迁移为普通 v7 批次缓存。
3. **原著快照记录分析来源参数。** 完成分析时保存模型、批次字符预算和 Prompt 版本，历史宇宙复用时按来源快照选择同一套批次布局和模型。
4. **历史入口的复用粒度是批次，SQLite 快照不是缓存前置条件。** 首先尝试合并当前宇宙已有、且与其 bounded 原文指纹完全匹配的旧批次缓存；该路径只做缓存校验和合并，不调用模型。没有完整本地缓存时，直接检查来源原著的批次缓存，不要求来源 `story_analysis` 快照存在或完整。按来源快照记录的模型与 `maxChars` 恢复批次布局；快照缺失时使用当前分析预算，并按模型候选逐一验证真实缓存。普通 v6 与已完成 delta 升级的 v6 批次均可复用。入口之前的完整批次直接复用；入口落在某批中间时，仅对该批入口前缀重新分析。入口之后的批次完全跳过。生成的子宇宙快照只包含截止入口的章节和来源引用。
5. **新宇宙不得回退为整本重分析。** 如果本地缓存、来源批次缓存和可安全过滤的来源快照均无法恢复，知识构建应明确失败并说明来源问题；不得静默在子宇宙从第一章重新分析原著。缺少来源 SQLite 快照本身不是失败理由，只要来源批次缓存足以恢复 bounded 快照。原著分析必须在来源原著世界完成。
6. **增量合并不调用模型。** `--merge-only` 只读取已完成且指纹匹配的缓存；缺失批次报告 pending，不能在该模式下补跑模型。

## 结果

- 原著追加章节或局部改文时，已验证且未变化的批次可以继续复用。
- 旧版本已经生成的 `.output/<universe>/story-analysis/<hash>/batch-xxxx.json` 不会被忽略；只要完整语料指纹精确匹配，就能通过 `--merge-only` 恢复到 SQLite。
- 新建故事宇宙不再重复分析完整原著；最多只需补分析入口所在批次的前缀。
- 不会把未来章节内容混入历史宇宙，也不会把不完整快照误标为完整。
- 如果旧缓存无法被精确证明属于当前原著，系统选择明确报错，而不是猜测或静默重跑整书。

## 验收标准

- 同一模型、Prompt 和批次预算下，改变一个批次正文只使该批指纹变化。
- 来源 `story_analysis` 行数为 0、但来源 v6/delta 批次缓存完整时，仍可恢复历史宇宙快照；不得因为快照缺失短路批次复用。
- 完整原著缓存可按入口复用所有此前完整批次；入口所在批次只传入入口及之前章节。
- 入口之后章节不进入子宇宙分析输入、快照或检索索引。
- 缺失来源批次时，知识构建失败并保留诊断，不启动子宇宙整本分析。
- `--merge-only` 不调用模型。
