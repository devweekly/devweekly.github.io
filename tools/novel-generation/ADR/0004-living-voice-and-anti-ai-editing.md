# ADR 0004：Living Voice、Anti-AI 编辑与读者体验

- 状态：Accepted
- 日期：2026-11-06
- 范围：`tools/novel-generation`

## 背景

现有写作流程已经包含主线规划、创意发散、章节蓝图、正文、对白修订、叙事声音修订和硬伤终审。仍然存在一类不同于事实连续性的质量问题：模板化修辞、空泛总结、人物同声、缺少人物视角的装饰性细节，以及解释过度。这些问题不能靠增加禁词或统计句长解决。

外部项目 awesome-novel-agent 提供了值得吸收的 Living Voice、Anti-AI 编辑、Style Distillation、Reader Agent 和角色推演沙盘思路。本项目只吸收适合现有架构的原则，不复制其 Agent 调度体系或未经逐文件许可核验的实现与知识文件。

## 决策

### 1. 文学性是最高优先级

文学性、文笔、艺术风格高于其他一切。Anti-AI 不是让作品通过 AI 检测器，也不是把文本改成统一口语腔。检测结果、统计特征和规则提示不能凌驾于作品的叙事声音、人物生命力、情绪感染力和阅读体验。

原稿成立时允许零修改。不得为了显示编辑工作量而改写，不得为了“像人写的”而制造错字、粗口、网络梗、固定口头禅或随机闲笔。

### 2. Living Voice 成为跨阶段创作原则

普通章节和长章节的 Writer、Dialogue Editor、Voice Editor 和 Anti-AI Editor 均在各自提示中注入同一份 Living Voice 原则：人物有当下目标；细节来自人物视角；性格通过选择呈现；对白承担关系动作；场景自然改变局势；世界观从行动和后果中显现；关键时刻允许慢写，重复过程允许概述。

这些原则用于激发判断，不是每场必须满足的模板。允许沉默、答非所问、矛盾、误判、偶然、留白与有意重复。

### 3. Anti-AI 作为现有流水线中的一个编辑阶段

在普通章节和长章节的叙事声音修订后、最终硬伤审查前增加共享的 Anti-AI 诊断、编辑与保守复核阶段。两条流水线调用同一组可复用提示原则，不建立新的常驻 Agent 或独立编排系统。

诊断只识别有具体文本证据的阅读问题，不估算 AI 生成概率。编辑只处理有明确阅读收益的局部。编辑后由独立复核比较原稿与编辑稿：只有确认有收益且没有明显损害时保留；收益不明确、语义/声音/情绪可能受损或复核失败时自动恢复原稿。不得改变剧情事实、因果、人物决定、信息揭示、叙事视角、人物关系和场景顺序；不得新增剧情事实。

编辑前后版本必须保留，并使用现有阶段缓存。输入正文、提示词、风格资料或模型阶段配置变化时，缓存指纹随之变化。

### 4. Reader 作为独立观察，不进入质量门禁

Reader 不读取人物档案、世界设定、章节蓝图、剧情摘要或作者意图，以盲读方式直接阅读正文，再报告追读意愿、注意力流失点、人物鲜活度、情绪抵达和场景记忆点。它不检查正史、不替代连续性终审，也不输出 blocker/major，不触发自动修复，不改变章节成功状态。

Reader 结果只作为运行诊断材料保存，不写入 Story State。

### 5. Style Distillation 作为风格资料演进方向

项目级 `style-profile.md` 保存抽象风格特征。现有 `distill-style` 命令可从授权样本提炼全局与场景级风格候选（对白、动作、打斗、群像、内心独白、环境、情感爆发等），通过代表性样本回归观察风格漂移。

候选经作者检查后可通过 `--activate` 显式激活，旧版先归档到忽略目录。尚无样本版本管理和自动风格回归工作台。不以统计相似度、句长或段落比例作为硬门槛；不得复刻特定作者的独特表达。

### 6. Roleplay Sandbox 为显式创作工具

角色推演沙盘由作者主动调用，不进入每章默认流水线。推演根据 Story State 中的人物动态状态、成书知识库人物长期观察，以及任务相关的故事图谱（人物互动、情节线、伏笔和关系边）探索互动；候选推演不自动成为正史，不直接更新 Story State。

### 7. 不新增专职常驻 Agent

不新增常驻 Anti-AI Agent、Reader Agent、Character Agent 或 Plot Agent 编排层。复用现有阶段调用、模型运行时、阶段缓存和运行目录。避免重复分析、重复上下文和额外调度复杂度。

## 后果

- 普通章节与长章节在叙事声音编辑后增加共享 Anti-AI 诊断、编辑和保守复核阶段；复核失败或无法确认收益时自动恢复编辑前正文。
- 终审仍只负责读者会认定“不可能”的硬伤；Anti-AI 与 Reader 不改变终审判定。
- 阶段产物可对比，Reader 结果可观察，但正常生成路径不等待人工确认。
- 机器规则不再以禁词、连接词频率、句长或检测器分数驱动正文改写。
- Style Distillation 与 Roleplay Sandbox 以 CLI 工具实现；风格候选显式激活，角色推演读取相关人物与故事图谱但始终不写正史。

## 验收标准

1. Anti-AI 阶段可零修改通过，不强制产生编辑差异。
2. 编辑不得改变剧情事实、人物决定、信息揭示和场景顺序。
3. 不机械删改连接词、修饰词、重复、长句、短句或段落。
4. 不统一人物声音，不添加人为口语特征。
5. Reader 评估与终审分离，不阻断或修复章节。
6. 普通章节和长章节复用同一 Living Voice / Anti-AI 诊断、编辑、复核原则与缓存机制。
7. 不增加常规人工审批步骤，不将候选推演写入正史。
8. Anti-AI 复核无法确认编辑收益时自动恢复原稿；不得把复核失败变成用户审批步骤。
9. Reader 盲读正文，不预先读取人物档案、蓝图或剧情摘要。
