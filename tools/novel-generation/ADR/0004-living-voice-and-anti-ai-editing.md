# ADR 0004：Living Voice、Anti-AI 编辑与读者体验

- 状态：Accepted
- 日期：2026-11-06
- 范围：`tools/novel-generation`

## 背景

现有写作流程已经包含主线规划、创意发散、章节蓝图、正文、对白修订、叙事声音修订和硬伤终审。仍然存在一类不同于事实连续性的质量问题：模板化修辞、空泛总结、人物同声、缺少人物视角的装饰性细节，以及解释过度。这些问题不能靠增加禁词或统计句长解决。

外部项目 awesome-novel-agent 提供了值得吸收的 Living Voice、Anti-AI 编辑、Style Distillation、Reader Agent 和角色推演沙盘思路。本项目只吸收适合现有架构的原则，不复制其 Agent 调度体系或未经逐文件许可核验的实现与知识文件。

## 决策

### 1. 文学性是最高优先级

文学性、文笔、艺术风格高于其他一切。Anti-AI 不是让作品通过 AI 检测器，也不是把文本改成统一口语腔。检测结果、统计特征和规则提示不能凌驾于作品的叙事声音、人物生命力、情绪感染力和阅读体验。

原稿成立时允许零修改。不得为了显示编辑工作量而改写，不得为了“像人写的”而制造错字、粗口、网络梗、固定口头禅或随机闲笔。

### 2. Living Voice 成为跨阶段创作原则

普通章节和长章节的 Writer、Dialogue Editor、Voice Editor 和 Anti-AI Editor 均在各自提示中注入同一份 Living Voice 原则：人物有当下目标；细节来自人物视角；性格通过选择呈现；对白承担关系动作；场景自然改变局势；世界观从行动和后果中显现；关键时刻允许慢写，重复过程允许概述。

这些原则用于激发判断，不是每场必须满足的模板。允许沉默、答非所问、矛盾、误判、偶然、留白与有意重复。

### 3. Anti-AI 作为现有流水线中的一个编辑阶段

在普通章节和长章节的叙事声音修订后、最终硬伤审查前增加共享的 Anti-AI 诊断、编辑与保守复核阶段。两条流水线调用同一组可复用提示原则，不建立新的常驻 Agent 或独立编排系统。

诊断只识别有具体文本证据的阅读问题，不估算 AI 生成概率。编辑只处理有明确阅读收益的局部。编辑后由独立复核比较原稿与编辑稿：只有确认有收益且没有明显损害时保留；收益不明确、语义/声音/情绪可能受损或复核失败时自动恢复原稿。不得改变剧情事实、因果、人物决定、信息揭示、叙事视角、人物关系和场景顺序；不得新增剧情事实。

编辑前后版本必须保留，并使用现有阶段缓存。输入正文、提示词、风格资料或模型阶段配置变化时，缓存指纹随之变化。

### 4. Reader 作为独立观察，不进入质量门禁

Reader 不读取人物档案、世界设定、章节蓝图、剧情摘要或作者意图，以盲读方式直接阅读正文，再报告追读意愿、注意力流失点、人物鲜活度、情绪抵达和场景记忆点。它不检查正史、不替代连续性终审，也不输出 blocker/major，不触发自动修复，不改变章节成功状态。

Reader 结果只作为运行诊断材料保存，不写入 Story State。

### 5. Style Distillation 作为风格资料演进方向

项目级 `style-profile.md` 保存抽象风格特征。现有 `distill-style` 命令可从授权样本提炼全局与场景级风格候选（对白、动作、打斗、群像、内心独白、环境、情感爆发等）。

候选经作者检查后可通过 `--activate` 显式激活，旧版先归档。激活后的资料由 CLI 在每次普通章节和长章节写作时自动加载，注入规划、创意发散、正文、对白与叙事声音相关阶段；不需要逐章指定。每章终审通过后自动执行只读风格回归，并将报告保存在本次运行目录。没有配置参考样本时，只能依据 Style Profile 做有限观察并明确证据不足。手动 `style-regress` 仍用于任意文件的专项对照。

当前尚未实现样本版本管理、跨章节自动批量趋势分析和 CI 风格门禁。不以统计相似度、句长或段落比例作为硬门槛；不得复刻特定作者的独特表达。

### 6. Roleplay Sandbox 为显式创作工具

角色推演沙盘由作者主动调用，不进入每章默认流水线。推演根据 Story State 中的人物动态状态、成书知识库人物长期观察，以及任务相关的故事图谱（人物互动、情节线、伏笔和关系边）探索互动；候选推演不自动成为正史，不直接更新 Story State。

### 7. 不新增专职常驻 Agent

不新增常驻 Anti-AI Agent、Reader Agent、Character Agent 或 Plot Agent 编排层。复用现有阶段调用、模型运行时、阶段缓存和运行目录。避免重复分析、重复上下文和额外调度复杂度。

## 后果

- 普通章节与长章节在整体文学编辑/逐场修订后执行共享 Anti-AI 诊断；只有诊断明确指出具体阅读问题时才编辑，空诊断、无问题或诊断失败均跳过整章改写；复核失败或无法确认收益时自动恢复编辑前正文。
- Editorial Review 只负责明确硬伤。发生硬伤修复时，在故事状态提交后追加只读文风回归观察；它不改稿、不阻断章节，也不影响状态提交。
- Reader 是可选的盲读观察，普通章节与长章节均通过 `--reader-experience` 显式启用；默认不增加一次完整章节模型调用。
- 阶段产物可对比，不增加常规人工确认步骤。
- 机器规则不再以禁词、连接词频率、句长或检测器分数驱动正文改写。
- Style Distillation 与 Roleplay Sandbox 以 CLI 工具实现；风格候选显式激活，角色推演读取相关人物与故事图谱但始终不写正史。

## 验收标准

1. Anti-AI 阶段可零修改通过，不强制产生编辑差异。
2. 编辑不得改变剧情事实、人物决定、信息揭示和场景顺序。
3. 不机械删改连接词、修饰词、重复、长句、短句或段落。
4. 不统一人物声音，不添加人为口语特征。
5. Reader 评估与终审分离，不阻断或修复章节。
6. 普通章节和长章节复用同一 Living Voice / Anti-AI 诊断、编辑、复核原则与缓存机制。
7. 不增加常规人工审批步骤，不将候选推演写入正史。
8. Anti-AI 复核无法确认编辑收益时自动恢复原稿；不得把复核失败变成用户审批步骤。
9. Reader 盲读正文，不预先读取人物档案、蓝图或剧情摘要。


### 5.1 风格资料自动应用与风格回归

激活后的项目风格资料由普通章节和长章节流水线自动加载，进入规划、正文、对白与叙事声音阶段。每次终审通过后，流水线自动运行只读风格回归：读取项目风格资料及可选的认可样本，生成运行报告。回归报告不自动改写正文、不阻断状态提交；手动命令只用于专项对照，不是正常写作步骤。

## 变更记录：2026-11-07——从表面 Living Voice 转向叙事力度

对实际生成章节的复盘发现，旧流程虽然强调克制、留白、短句可用和动作外化，但章节蓝图仍会把文学效果拆成具体微动作（例如停顿时长、伸手前看手、伸手后收手、反复推放物件）。正文模型逐项执行后，产生“动作逐帧化、短句堆叠、机械留白、解释潜台词”的文青腔。Anti-AI 诊断能发现部分问题，但编辑复核容易把删除重复动作误判为损失，恢复了原稿。

因此补充以下决策：

1. 蓝图只描述场景功能、人物欲望与压力、信息差、关键选择和后果；不写微动作脚本、停顿时长、句子、比喻或心理解释。每场最多保留一两个不可丢失的戏剧锚点。
2. 正文生成不把蓝图当作逐项执行的舞台指令。作者 Agent 可以合并、替换或省略非必要动作，只要保留戏剧功能和事实连续性。
3. 风格诊断必须检查全章累积效果，特别是动作逐帧拆解、短句/断行密度、重复否定式收束、同一种停顿反复出现，以及画面之后的解释性旁白。不能只逐句判断是否通顺。
4. 编辑可以合并动作、压缩解释、重组句子和段落；复核应判断信息、因果、人物选择、人物声音和情绪效果是否真正受损，不得把“字句减少”或“原稿更长”当作损失证据。
5. “锋利”不等于短句、冷峻、含蓄或诗意。其核心是准确选择、信息差、具体利害、行动后果和人物判断。允许长句、直接判断、粗粝表达与必要铺陈。
6. 风格回归若没有真实认可样本，只能报告“缺少样本，无法判断与原著的风格距离”；不得据抽象 Style Profile 得出“没有风格漂移”的结论。

这些改动不建立新 Agent，不引入字数/句长门槛，也不要求复刻作者独特表达；继续以文学性、文笔、艺术风格高于其他一切为最高原则。


## 变更记录：2026-11-07——去 AI 味前后处理与编辑减负

参考仓库级 `skills/article-de-ai/SKILL.md` 的方法论，并吸收 MIT 项目 [blader/humanizer](https://github.com/blader/humanizer) 的结构性信号：staged opener、空转的否定式对照、重复段尾、格言式收束、强行三项排比和机械句首。先判断真实阅读问题，再按上下文编辑；诊断项是线索而非关键词黑名单；检查不等于必须修改；编辑后保护原意、作者判断和有效表达。Humanizer 的通用规则不作为小说的禁令，参考样本/项目风格资料优先于通用清单。`article-de-ai` 面向技术文章和报告，其列表密度、段落结构等文档规则不直接套用到小说。小说需要额外判断人物声音、叙事视角、意象、信息遮蔽、伏笔和节奏功能。

正式流水线调整为：

1. **Editorial Review 前：文学去 AI 味编辑。** Writer 和整体文学编辑完成后，执行有证据的 Anti-AI 诊断；只有诊断明确指出值得修改的问题才执行编辑。诊断为空、明确无问题或诊断失败时跳过编辑，不允许在没有证据时重写整章。编辑后仍执行语义/叙事功能复核；无法确认收益时恢复编辑前版本。
2. **Editorial Review：只负责硬伤。** 不把 AI 味、文风偏好、人物弧光、伏笔进度和节奏指标混入硬伤门禁。只修复明确影响事实成立或读者理解的问题。
3. **Editorial Review 后：文风回归观察。** 只有终审确实执行过修复时，才比较修复前正文与最终正文，检查修复是否意外引入模板化总结、重复解释、机械转折、人物同声或过度说明。该检查只读、不改稿、不阻断章节、不触发第二轮自动润色；没有修复则跳过。
4. **普通章节与长章节一致。** 两条链路共用同一诊断、编辑、复核和后置观察提示。长章节不得在诊断无问题、诊断失败或没有明确问题时仍然执行整章 Anti-AI 改写。

去 AI 味的目标不是把小说改成简洁、口语、短句或所谓“人类文本”，而是消除没有信息增量的重复、解释过度、机械转场、抽象情绪标签、同构收尾、过度完整且同声的对白，以及动作逐帧化等真实阅读问题。任何判断必须结合当前场景与全章累积效果；允许有意复沓、复杂句、长段落、修辞、留白、闲笔和人物独特表达。

新增运行产物：`10-post-review-literary-check.md`（仅在发生终审修复时生成）；失败只记录错误，不影响章节交付。没有终审修复时生成 skipped 记录。新增共享判断函数与测试，确保空诊断/明确无问题不会触发整章改写。
