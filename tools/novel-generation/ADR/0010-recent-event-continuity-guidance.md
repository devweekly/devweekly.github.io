# ADR 0010：近期事件上下文与情节去重提示

- 状态：Accepted
- 日期：2026-11-10

## 背景

现有 Story Plan、滚动 Story Arc、World Situation 和 Story State 已经提供长期方向、人物当前状态、近期事件、关系、伏笔及 MacGuffin。普通章节和长章节也已复用这些资料。

仍有一个低成本缺口：事件虽然进入上下文，但规划提示没有明确要求模型比较近期事件的语义内容。模型可能更换人物、地点或措辞，重复安排相同的线索发现、背景解释、冲突和解决过程。反过来，机械禁止旧事件再次出现，又会破坏伏笔回响、旧事重释和冲突升级。

## 决策

新增纯确定性函数 `buildRecentEventContinuityContext`，从现有 Story State 的事件序列中取最近 8 条，按记录顺序输出摘要和后果，并限制在 1,800 字符内。

普通章节与长章节共用该函数。结果进入现有规划上下文，不新增 Agent、不新增模型调用、不新增数据库表，也不改变 Story State 的权威边界。

提示明确区分：

- **冗余重复**：只换人物、地点或措辞，再次安排同一发现、解释、冲突或解决过程，却没有新的信息或后果。
- **有效呼应**：旧事件再次出现，但带来新的信息、意义、代价、关系变化、局势后果，或改变人物对过去的理解。

不要求每章引入新事件；日常、过渡、停留和关系戏仍然成立。此机制只辅助规划，不做语义硬过滤，也不把推演写入 Story State。

## 缓存与诊断

近期事件上下文是模型 Prompt 的组成部分，现有阶段缓存指纹会自然包含其内容；事件变化后相关规划缓存自动失效。每次运行额外保存 `00-recent-event-context.md`，便于核对规划器实际看到了哪些近期事件。

## 验收

1. 上下文最多包含最近 8 条事件，按 Story State 顺序排列，且不超过 1,800 字符。
2. 没有事件时不生成空占位内容。
3. 普通章节与长章节均注入同一上下文。
4. 提示同时禁止无新增意义的重复，并明确允许有新信息/后果的有效呼应。
5. 不新增模型调用、Agent、数据库表或人工审批步骤。
6. 现有文学性优先原则不变。
