# ADR 0003：自主执行优先，人工介入例外

- 状态：Accepted
- 日期：2026-11-06
- 范围：`tools/novel-generation`

## 背景

小说生成系统的目标是从创作任务出发，自主完成规划、生成、修订、质量检查、状态提取和持久化。工作台最初把 Story Plan 设计成 draft candidate，必须由用户批准后才激活。这把“查看结果”变成“流程继续的前置条件”，与全自动续写目标冲突，也容易把人工审批变成日常操作负担。

人工审核仍有价值，但主要用于观察运行质量、检查历史版本、主动修改创作方向，以及处理系统无法安全解决的异常。它不应成为普通任务的同步依赖。

## 决策

### 1. 默认自主完成

普通任务必须沿自动路径完成，不设置必须人工 review、approve 或 confirm 才能进入下一阶段的状态。工作台用于查看进度、产物、质量诊断和历史，不是审批中心。

Story Plan 生成后先执行 schema、World ID 和基础业务校验；校验通过即自动激活，并将旧版本归档。CLI 与 Web 遵循相同默认行为。只有显式使用 `--draft` 的实验任务才生成不影响正式写作上下文的草稿。

### 2. 自动修复有边界，失败不伪装成功

质量审查发现明确硬伤时，系统先按有限轮数自动修复并复查。达到上限仍未解决，任务安全失败，保留正文、诊断和 checkpoint，不提交 Story State。不得静默接受 blocker，也不创建等待人工批准的普通队列。

失败后用户可以主动检查原因、调整输入或重新运行；正常成功路径不等待用户操作。

### 3. 仅在必要时请求人工介入

以下情况可以暂停并请求人工决策：

- 权威 Story State 或版本之间发生无法自动协调的冲突；
- 权威数据损坏，自动恢复可能造成事实丢失或覆盖；
- 系统无法判断哪一种恢复方式安全，继续执行可能污染正史；
- 不可逆、破坏性或安全敏感操作需要明确授权。

模型偏好、普通规划取舍、章节润色、对白修改、常规连续性检查和可回滚版本更新不构成人工介入理由。

### 4. 保留可观察性和可逆性

每次运行保留输入、产物、质量摘要、模型信息和错误现场。自动应用的 Story Plan 版本必须可追溯，旧版本归档；人工检查和回滚属于用户主动发起的管理操作，不构成生成流程的审批门禁。

### 5. 文学性优先原则不变

自主执行不意味着增加更强的规则约束。人物行为、主线、伏笔和分析结果仍是创作参考。质量门禁只处理明确破坏故事成立或读者理解的硬伤；不得为了提高结构完整度、字段覆盖率或审查通过率牺牲文学表达。

## 后果

- Web Workbench 从审批队列转为运行观察和版本追溯界面。
- Story Plan 生成成功后自动生效；旧版本归档，用户可事后检查。
- CLI `plan-story` 默认激活，`--draft` 只用于隔离实验。
- 章节终审在有限自动修复后仍失败时，安全终止本次运行并保留现场，而不是等待人工批准后继续。
- 后续新增 Web 写作能力必须复用现有自动工作流，不得另建一套以人工审批为默认的执行路径。
