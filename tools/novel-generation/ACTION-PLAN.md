# 小说续写能力改造 Action Plan

- 状态：四个阶段已实施
- 日期：2026-11-06
- 范围：tools/novel-generation

## 目标与边界

借鉴 D&D Campaign 对世界设定、人物自主行动、局势变化和长期记录的处理方式，提升长篇小说续写的可信度与连续性。最终产物仍然是小说正文；所有分析和推演只是辅助写作。文学性优先于结构完整、字段覆盖和指标。

遵循 ADR 0003：普通流程自动执行，人工观察和干预是可选能力。推演结果不是正史，只有最终正文实际发生的事实才能进入 Story State。

不引入 D20、属性检定、等级、HP、回合制、任务奖励、玩家/DM 交互；不建独立 Campaign 数据库、全世界模拟器或专职 DM Agent；不引入图数据库或向量数据库承载这些能力。

## Phase 1 — 人物动态状态与因果连续性（P0）

- [x] 在 Story State 人物快照增加可选字段：motivation、resources、constraints、currentPressure、decisionHistory。
- [x] 普通章节与长章节状态提取只记录正文有依据的当前状态。
- [x] 让普通章节与长章节的规划/场景上下文都能读取相关人物动态信息。
- [x] 事件增加可选 causes、relatedPlotThreads，表达前因和相关剧情线。

验收：人物行动有动机依据，知识范围不全知；字段缺失不阻塞旧状态；状态不记录正文未发生的事。

## Phase 2 — 章节前轻量级 World Situation（P1，已完成）

- [x] 基于 Story State、Story Plan、相关人物档案、剧情线和本次任务构造局势输入。
- [x] 复用现有主线 Planner 生成局势推演，不新增 Agent，也不增加独立模型调用。
- [x] 只向 Planner 提供少数与本章有关的人物/势力的目标、动机、知识、资源、限制和压力。
- [x] 仅在有叙事价值时考虑主角不介入的可能发展；不模拟整个世界，不要求每个 NPC 都行动。
- [x] 将推演作为暂定创作素材交给章节主编，绝不直接写入 Story State。
- [x] 普通章节和长章节采用一致的边界；推演内容只保存为运行产物，不修改正史状态。

验收：推演能为正文提供有用的人物行动动机或冲突，但不会把可能性写成事实，也不会让剧情模板化。

## Phase 3 — 剧情单元、伏笔与上下文恢复（P2，已完成）

- [x] Planner 可选考虑核心矛盾、参与者、信息差、阻碍和代价，不要求每章套用模板。
- [x] 因果关联复用 Story State 的 causes 与 relatedPlotThreads；按事件 ID 展开前因、按剧情线 ID 展开标题，不另建事件图谱。
- [x] 伏笔继续复用现有 novel_foreshadowings 和 writing brief；将 Story Plan 纳入检索查询，使计划涉及的人物、剧情线与伏笔能参与上下文筛选，不要求每章回收。
- [x] 按当前章节选取近期事实、人物状态、剧情线和相关伏笔；World Situation 只注入少量相关状态、近期事件及因果，不把整本分析灌入上下文。
- [x] 普通章节和长章节复用同一 World Situation 构建器；保留现有状态更新、阶段缓存和恢复路径。

验收：章节能承接重要事实和人物变化；伏笔不因上下文截断轻易遗忘；日常、闲笔、留白和意外仍然成立。

## 实施顺序

前三个阶段已接入现有写作链路；第四阶段补齐续写中的关系、伏笔与 MacGuffin 动态记录。后续只在真实续写中发现上下文遗漏或人物行动失真时修正筛选和提示，不再为这些能力增加独立 Agent、数据库或审批步骤。代码交付仍应通过项目 typecheck 与 build；自动恢复必须有界并保留 checkpoint。

## Phase 4 — 续写动态关系、伏笔与 MacGuffin 生命周期（P1，已实施）

- [x] 普通章节和长章节终审后的状态提取，记录本章确实发生的伏笔埋设、强化、误导、揭示、回收或放弃。
- [x] 记录重要目标/物件/信息的引入、追寻、持有者与位置变化、遗失、转移或失效。
- [x] 记录重要人物关系中有正文依据的互动与变化，形成跨章节关系时间线。
- [x] 每条变化必须引用最终正文中的逐字证据；无自然变化时不生成记录。
- [x] 使用稳定更新 ID 追加到 Story State，checkpoint 恢复时幂等合并；不污染原著 `novel_*` 分析快照。
- [x] 普通/长章节规划上下文按任务相关性读取最新状态；终审只检查明确事实冲突，不要求每章推进或回收。
- [x] 为证据校验、生命周期追加、恢复幂等和上下文筛选增加测试。

## 明确不做

不把章节转成任务、遭遇或回合；不以游戏数值决定人物能力和胜负；不模拟所有人物日常；不要求每个人物都有冲突或成长节点；不让伏笔、人物弧光或 Story Plan 成为正文必须兑现的清单；不增加专职 Agent 或复杂基础设施，除非后续证据证明现有模块无法满足续写质量要求。
