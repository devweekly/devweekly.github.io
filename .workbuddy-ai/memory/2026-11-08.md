# 2026-11-08

## 诊断：「原文目录与 novel.db 数量章节不一致」

报错来自 `src/server.ts:749`（Create Universe 的防泄漏校验）：
```ts
const chapterCount = SELECT COUNT(*) FROM novel_chapters;
if (chapterCount !== canonChapters.length) throw new Error("原文目录与 novel.db 章节数量不一致…");
```

### 实测（conghuoniao）
- `analysis/conghuoniao/chapter-index.json`：`chapterCount = 753`，17 卷，title 唯一 749。
- `worlds/conghuoniao/library/index.json`：2594 chunks，按连续 `chapter` 分组 = **754 组**。
  多出的 2 组是「前置内容」和一段作者单章（`第三卷剧情问题，啊，也没必要和读者详细说了…`），
  catalog 明确不计入章节数。catalog 的 753 个 title 全部能在 groups 里找到。
- 报错时 `novel.db` 所有派生表几乎全空：`novel_chapters=0`、`novel_beats=0`、
  `novel_characters=0`、`story_analysis=0`；只剩 `novel_arcs=17`、
  `novel_character_profiles=28`、`world_meta=1`（`clearNovelAnalysis` 没删这两张）。

### 根因（两层）
1. **数据被清空**：`src/library.ts:181` 的 ingest 调用 `invalidateDerivedAnalysis()`
   （`database.ts:263`），执行 `DELETE FROM story_analysis; DELETE FROM novel_chapters;` +
   `clearNovelAnalysis()`。之后没有跑 `index-story` 回填，所以 DB 0 章 vs 目录 754 章。
   报错文案说「请重新导入并构建索引」有误导性 —— 再 ingest 只会再清空一次。
2. **代码口径不一致（真 bug）**：`readCanonChapters()`（`server.ts:504`）从
   `library/index.json` 按连续 title 分组得 754；而 `indexNovelStructure` →
   `syncNovelChapters` 按 `chapter-index.json` 写 753 行。
   即使回填，`753 !== 754` 仍会失败；且 `server.ts:750` 用 `LIMIT 1 OFFSET selectedIndex`
   把含 2 个额外项的目录索引当 DB 行偏移，起点会错位 1~2 章。
   重复章名（749 unique / 753）让「按 title 查找」也有歧义。

### 已执行（数据缓解）
`node --import tsx src/cli.ts index-story --world conghuoniao`：
```
chapters: 753, chunksMapped: 2594, chaptersWithoutChunks: 1,
unmatchedLabels: ["前置内容", "第三卷剧情问题…"], characters: 18, mentions: 1536
```
回填后 `novel_chapters = 753`，`MIN/MAX(ordinal) = 0/753`（有一个序号跳号）。
**但校验仍会失败**，因为 754 vs 753 的代码口径问题未修。

### 建议修复（未落地，涉及未来剧情泄漏边界，需用户确认）
- `readCanonChapters` 以 `chapter-index.json` 为骨架，用双指针序列对齐 catalog title
  与 library groups，跳过 `unmatchedLabels`，返回带 `catalogIndex` 的 753 章。
- `/source-chapters` 返回 `id = catalogIndex`；`entryChapterIndex` 语义改为 catalog 序号。
- Create Universe 数量校验改为 `chapterCount === catalog.chapterCount`；
  `entryRecord` 用 catalog 序号定位，不再用含额外项的目录下标做 OFFSET。
- 必须跑 universe 相关集成测试；改错会让新宇宙读到起点之后的剧情（不可逆污染）。
