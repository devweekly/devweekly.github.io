# 文章去 AI 味

## Goal

让文章读起来像人写的：段落自然、格式克制、措辞平实。

只动排版与措辞，不动内容。核心原则：

> **合并碎段、降级滥用格式、保留全部句子与观点。**

## “AI 味”清单（只修这些）

### 1. 碎段

一句话甚至一个词单独成段、连续多个短段堆叠 → 合并成自然段落。句子本身保留，最多做连接词微调。

### 2. 滥用加粗

整句加粗、每个小节都有加粗“金句” → 只保留真正的关键术语加粗，其余去掉 `**`。

### 3. 滥用引用块

动不动用 `>` 包一段结论 → 全文只保留 2–3 个真正核心的结论用引用块，其余并入正文。

### 4. 孤立单词成段

如 testing / evaluation / monitoring 各占一行 → 合并成无序列表或一句中的枚举。

### 5. 斜体当小标题

独立成段的 `*...*` → 改为 `###` 三级标题或并入正文。

### 6. AI 腔措辞降频

“不是……而是……”排比、“非常重要”、“关键在于”、“本质上”、“值得注意的是”、“归根结底”——保留观点，换成平实说法；不要引入新的排比句式。

## 严禁事项

- 不许改 frontmatter、任何标题文字与层级。
- 不许碰代码块（含 mermaid）、表格内容、链接 URL。
- 不许增删观点、论据、数据、案例；不许缩写篇幅（合并段落但保留全部句子）。

## 大文件策略

超过约 1500 行时，按 `#` / `##` 标题边界切成多块（块边界必须落在标题行或空行，不得切断段落），多块并行改写后按顺序拼接。

## 校验（写回后必须执行）

1. 标题逐字同序：新旧文件的 `^#+ ` 行必须完全一致（数量、文字、层级、顺序）。
2. 代码围栏配对：全文 ` ``` ` 数量为偶数；mermaid / yaml / json 块数量符合预期。
3. 引用链接定义无缺失（如 `[1]:`–`[42]:`）。
4. `astro build` 通过；抽查页面渲染正常。
