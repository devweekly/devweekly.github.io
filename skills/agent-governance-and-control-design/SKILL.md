# Agent Governance & Control Design

## Goal

把「谁被允许做什么、谁批准、出事怎么办、凭什么证明」落成一条可执行、可取证、可停止的控制链。

核心原则：

> **LLM 可以提出「我要做什么」，但不能决定「我被允许做什么」。**

这条原则是本 skill 的第一判据。任何架构评审只要发现授权判定由模型输出决定，直接判 Gap，不进入后续步骤。

## 何时用 / 不适用

| 用 | 不用 |
| --- | --- |
| 设计 Agent 的风险分级与控制档位 | 威胁与控制落点的对应（用 `agent-security-threat-review`） |
| 设计审批流、例外通道、紧急终止 | Runtime 是否支持这些控制（用 `agent-runtime-boundary-review`） |
| 定义 SoD、双人控制、风险接受 | 逐条评分与整改（用 `agent-well-architected-assessment`） |
| 评审「谁能改 Policy」「谁能扩权限」 | Tool 准入与注册（用 `agent-tool-and-mcp-governance`） |

## 输入

| 输入 | 必需 | 说明 |
| --- | --- | --- |
| 用例清单与业务重要性分级 | ✅ | 风险分级的输入 |
| 现有 IAM / Policy / 审批系统能力 | ✅ | 决定控制落在哪一层 |
| 监管义务与内部政策清单 | ✅ | 决定哪些控制不可协商 |
| Agent Registry 或等价清单 | 建议 | Owner 与控制绑定的载体 |
| 事故与近失事件 | 可选 | 校准分级阈值 |

## 控制链（主干模型）

```text
Risk Classification
        ↓   等级决定控制强度，不是文档装饰
      Policy          谁能做什么（可执行、可版本化）
        ↓
  Authorization       由确定性引擎裁决，不是由 LLM 裁决
        ↓
     Approval         风险分级的函数：HITL / HOTL / 自动
        ↓
    Execution         受预算、能力、隔离约束
        ↓
  Audit Evidence      可重建、不可篡改、保留期可证
```

任一环缺失，整链判为**未建立**——不要因为「前四环都有」就给通过。

## 第一步：风险分类（Risk Classification）

| 等级 | 判定特征 | 典型控制 | 允许的 autonomy |
| --- | --- | --- | --- |
| **L0** | 无副作用，纯信息整理 | 日志 + 抽样复核 | 可全自主 |
| **L1** | 可逆内部动作（草稿、查询、读） | 日志 + 配额 + 事后复核 | 可全自主 |
| **L2** | 可逆但有外部可见影响 | 审批抽检 + 二次确认 | 受限自主 |
| **L3** | 资金 / 客户 / 授信 / 合规相关，可回滚 | 强制事前审批 + 双人控制 | 仅建议 |
| **L4** | 不可逆或监管级决策 | 人工权威边界 + 独立审批 + 强制证据 | 禁止自主 |

分级必须由**用例属性**决定，不由模型能力或团队意愿决定。L4 的控制属**内部标准**，不要写成「监管要求」。

判据：
- 分级结论有依据条款与确认人；
- 分级**驱动** autonomy 上限、审批层级、日志与证据要求（否则分级无效）；
- 分级会随用例变化重新评审，有复核日期。

## 第二步：Policy 设计

| 要点 | 判据 | 反模式 |
| --- | --- | --- |
| 可执行 | Policy 是机器可判定的规则，不是文档段落 | Policy 写在 wiki 里靠人执行 |
| 版本化 | 每次变更有版本号、差异、生效时间、审批人、可回滚 | 直接改生产配置 |
| 归属 | 明确的 Policy Owner 与变更审批人 | 平台团队默认拥有所有策略 |
| 分层 | Agent / Action 治理归 Agent Platform；Model 治理归 AI Platform；Entitlement 归 IAM 与数据平台 | 一套 Policy 管到底 |
| 冲突裁决 | 冲突时的优先顺序成文且可自动执行 | 由 Agent 自行取舍 |

## 第三步：Authorization 与权限边界

- 判定发生在**调用链的 PEP**（Retrieval / Tool / Egress），不是发生在提示词里。
- 权限边界位于 Agent 之外，Agent 不可自修改；有越权尝试被拒的证据。
- 委派（delegated identity）必须带来源、时限、范围，可反查原始主体，且**不放大**权限。
- 拒绝是默认值：依赖不可用时 HIGH / CRITICAL 一律 DENY。

| 检查问题的正确形状 | 错误形状 |
| --- | --- |
| 授权判定是否由确定性引擎给出并留痕？ | Agent 是否知道自己的权限？ |
| 依赖不可用时是 DENY 还是 ALLOW？ | 是否有异常处理？ |

## 第四步：Approval 设计

| 维度 | 必须写清 | 不写清的后果 |
| --- | --- | --- |
| 触发条件 | 什么动作、什么金额或范围阈值 | 审批变成随机行为 |
| 审批层级 | 一档、双人、还是独立审批人 | 谁都能批 |
| 呈现信息 | 事实证据与待执行动作（不是结论与建议） | 人工只能机械点击批准 |
| 超时行为 | 超时默认值（通常 DENY），不依赖人工在线 | 请求堆积后被批量放行 |
| 回避规则 | 谁不能批准谁（申请人、开发者、利益相关方） | 自我批准 |
| 修改能力 | 审批人可提出修改并回传 | 只能批 / 拒 |
| 认知负荷 | 批量、限流、分组、优先级 | 审批疲劳导致全部放行 |

**四条硬要求**：审批不是确认按钮；拒绝、修改、超时、不可用四种人工状态都必须有确定性后续；审批人看到的必须是**事实证据**而不是模型结论；审批记录必须与版本、评估结果绑定。

## 第五步：职责分离与双人控制

| 控制 | 要求 | 判据 |
| --- | --- | --- |
| SoD | 开发 / 审批 / 部署 / 生产访问权限互斥 | 存在互斥矩阵，且矩阵被系统强制 |
| 双人控制 | 高风险动作需两人独立批准 | 两人不可为同一人代签，有时间戳 |
| 独立审批 | 审批人独立于交付方与受益方 | 审批人名单可反查组织关系 |
| 生产变更隔离 | 开发不能直接改生产 Prompt / Policy / 权限 | 生产权限只授予流水线身份 |

## 第六步：Kill / Break-glass / Fail-closed

| 机制 | 判据 | 不达标形态 |
| --- | --- | --- |
| Kill switch | 存在不依赖 Agent 配合的独立停止路径；有演练记录、生效时限、责任人；Agent 无法自行阻止 | 靠改提示词、靠等待其结束 |
| Run-level cancel | 单个 Run 可取消且状态可收敛 | 只能停整个平台 |
| Break-glass | 紧急通道有双人控制、时限、事后必审、留痕 | 存在长期有效的应急账号 |
| Fail-closed | 依赖不可用时高风险一律 DENY；有拒绝样本 | fail-open 且无补偿控制 |
| 降级语义 | 降级后仍不越权、仍留证 | 降级即绕过授权 |

## 第七步：Audit Evidence 设计

工程遥测与审计证据必须**分开**：

| 维度 | 工程遥测 | 审计证据 |
| --- | --- | --- |
| 用途 | 排障、性能、调优 | 监管、法务、非否认 |
| 保留 | 按运维需要 | 覆盖监管保留期 |
| 完整性 | 可采样 | 不可篡改、链式可验 |
| 访问 | 工程团队 | 受控且留访问记录 |

证据必须能回答：谁批的、批的是什么版本、依据什么数据与策略、结果如何、失败原因是什么、能否被第三方复核。

## 第八步：风险接受

| 情形 | 允许 | 形式要求 |
| --- | --- | --- |
| 控制已落地 + 有证据 + 影响有硬上限 | ✅ | 残余风险登记 + 接受人 + 到期复核日 |
| 控制已落地 + 无证据 | ⚠️ | 限期取证，期间不得进生产 |
| 控制未落地 + 风险 L3 / L4 | ❌ | 阻断，不允许风险接受 |
| 例外（临时放行） | ⚠️ | 双人批准 + 时限 + 补偿控制 + 到期强制复核 |

**P0 控制属架构前提（architectural prerequisite）**：未落地即 Production Gate 未满足，只能走例外流程 + 风险接受，且接受人必须是业务与风险双方。

## 反模式总表

| 反模式 | 为什么错 | 正确做法 |
| --- | --- | --- |
| 让 LLM 决定授权 | 模型是概率性的，授权必须可复现 | 由确定性引擎裁决 |
| 审批做成确认按钮 | 人工承担了责任却没获得判断能力 | 呈现事实证据与可选项 |
| Policy 写在文档里 | 无法强制、无法审计 | 可执行、版本化、可回滚 |
| 风险分级不驱动控制 | 分级变成装饰 | 等级到控制的一一对应 |
| 用「人工兜底」代替控制 | 责任不可持续 | 明确控制点 + 人工只做权威判断 |
| 例外长期有效 | 例外会变成事实标准 | 一律带时限与强制复核 |
| 审计日志与工程日志同库同策略 | 保留与完整性无法满足监管 | 分离并分别举证 |
