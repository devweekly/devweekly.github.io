# 报告规范（Report Schema）

> 本文档定义 Repository Research 的输出契约。报告必须遵循此 Schema。

---

## Repository Model Schema

Repository Model 是编译的**第一产物**，是知识图谱，不是文档。

### 节点（Node）

| 字段 | 说明 |
|------|------|
| **id** | 唯一标识（能力名，如 "调度器"） |
| **type** | 节点类型（capability / module / subsystem / runtime / config） |
| **owns** | 拥有的文件路径 |
| **attributes** | 语言、稳定性、可见性、置信度 |
| **evidence** | 证据引用列表 |

### 边（Edge）

| 字段 | 说明 |
|------|------|
| **from** | 源节点 id |
| **to** | 目标节点 id |
| **type** | 关系类型（owns / calls / depends_on / implements / extends / loads） |
| **evidence** | 证据引用列表 |

### 示例

```mermaid
flowchart TD
    S[调度器] --owns--> T[任务队列]
    S --calls--> P[插件管理器]
    P --loads--> E[扩展点]
    E --implements--> A[公共 API]
```

---

## 仓库模型维度

阶段 1 产出的 Repository Model 必须描述以下 5 个维度：

| 模型 | 描述 |
|------|------|
| **结构模型** | 模块、目录、组件及其边界 |
| **行为模型** | 控制流、数据流、运行流程 |
| **归属模型** | 状态、职责、生命周期归属 |
| **扩展模型** | 插件机制、扩展点、公共 API |
| **演进模型** | 架构演进与历史变化 |

---

## 阶段 2 输出类型

阶段 2 的架构解释必须产出以下类型的内容：

- 工程约束
- 架构作用力
- 设计决策
- 权衡
- 有意省略
- 架构张力
- 杠杆点
- 维护者心智模型

如果存在多个合理解释，分别说明并给出各自证据与置信度。

---

## 证据链

每一个非平凡结论都必须能够追溯到证据链。

```mermaid
flowchart TD
    A[结论] --> B[解释]
    B --> C[证据]
    C --> D[仓库产物]
    D --> E[文件 / 符号 / 提交]
```

证据来源：

| 来源 | 说明 |
|---------|------|
| 源代码 | 实现层面的直接证据 |
| 文档 | README / ADR / RFC / 设计文档 |
| 配置 | 构建配置 / CI 配置 / 部署配置 |
| 测试 | 测试用例反映的预期行为 |
| Git 历史 | 提交历史反映的演进意图 |
| 仓库元数据 | package.json / Cargo.toml 等 |

多个独立来源相互印证时，优先于单一来源。

---

## 置信度等级

每个解释必须标注置信度。置信度反映证据质量，而非模型确定性。

| 等级 | 要求 |
|------|------|
| **高** | 多个独立证据来源相互支持 |
| **中** | 证据存在，但解释仍有不确定性 |
| **低** | 证据薄弱或仅间接推断 |

---

## 未解问题格式

研究结束后仍可能存在无法验证的问题。每项必须包含：

| 字段 | 说明 |
|------|------|
| **问题** | 待回答的问题 |
| **缺失证据** | 缺失的证据类型 |
| **置信度影响** | 对整体置信度的影响 |
| **建议下一步调查** | 建议的下一步调查方向 |

---

## 报告章节

报告是 Repository Model 的一种视图，必须包含以下 17 个章节：

| # | 章节 | 说明 |
|---|------|------|
| 1 | **执行摘要** | 执行摘要 |
| 2 | **仓库心智模型** | 维护者心智模型 |
| 3 | **架构不变量** | 架构不变量 |
| 4 | **工程约束** | 工程约束 |
| 5 | **能力地图** | 能力地图 |
| 6 | **静态架构** | 静态架构 |
| 7 | **运行时架构** | 运行时架构 |
| 8 | **架构演进** | 架构演进 |
| 9 | **关键决策** | 关键决策 |
| 10 | **架构作用力** | 架构作用力 |
| 11 | **设计张力** | 设计张力 |
| 12 | **架构杠杆** | 架构杠杆点 |
| 13 | **可复用模式** | 可复用模式 |
| 14 | **风险** | 风险 |
| 15 | **经验教训** | 经验教训 |
| 16 | **未解问题** | 未解问题 |
| 17 | **证据质量摘要** | 证据质量摘要 |

**可从同一 Repository Model 生成其他视图**：安全报告、性能报告、API 指南、入职指南等。

## 知识单元格式

Repository Model 的可链接知识单元（每个能力/子系统一个 Markdown 文件）：

```
repository-model/
├── runtime.md
├── scheduler.md
├── plugin-system.md
├── configuration.md
└── storage.md
```

每个知识单元包含：

| 字段 | 说明 |
|------|------|
| **标题** | 能力/子系统名称 |
| **职责** | 这个能力做什么 |
| **节点** | 相关的 Model 节点 |
| **关系** | 与其他能力的关系 |
| **证据** | 支撑证据引用 |
| **不变量** | 此能力假设的架构不变量 |
