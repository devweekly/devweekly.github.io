# 2026-09-21

## 排查并修复 GitHub Actions `Deploy to GitHub Pages` 全部失败

**结论**：不是 workflow/权限/依赖问题，是**一篇 post 的 frontmatter 日期写错**，
Astro content collection schema 校验不通过，build 直接退出 1。

```text
报错：[InvalidContentEntryDataError] blog → ai-courses大学 data does not match collection schema.
      pubDatetime: Expected type "date", received "string"
      Location: src/content/blog/ai-courses大学.md:0:0
```

根因：`pubDatetime: 2026-09-014T02:02:03Z` —— 日期写成三位数 `014`，
YAML 不认为是时间戳，于是按字符串交给 zod，`z.date()` 校验失败。改为 `2026-09-14T02:02:03Z`。

### 定位过程（可复用）

1. `gh run list --limit 40` 看结论分布 → 全是 failure，说明不是偶发。
2. `gh run view <id> --log-failed | grep -iE "error|ERR_|exit code"` 直接取错误行
   （日志头部几十行都是 runner 样板，没用；错误在 390 行之后）。
3. `git log -- <file>` + 对照 `gh run list --json headSha` 找到**首个失败提交**：
   最后一次 success 是 `e03422b6`（2026-09-13），之后 `1e636b2e` 起连续 11 次失败 ——
   该提交正是加入这篇 post 的那次，因果闭合。
4. 全库扫描确认真伪范围：脚本遍历 `src/content/blog/*.md`（168 篇），
   用 `datetime.fromisoformat` 校验 `pubDatetime`，**只有这一篇非法**。
5. 本地跑 `./node_modules/.bin/astro build` 验证 → 286 页构建通过。

**踩坑**：`node_modules/.bin/astro` 是 shell wrapper，用 `node ./node_modules/.bin/astro`
会报 `SyntaxError: missing ) after argument list`；要 `export PATH=<managed node>/bin:$PATH`
后直接执行该 wrapper（macOS 还没有 `timeout` 命令，用 `gtimeout` 或别包）。
