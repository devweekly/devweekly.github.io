## 收窄 novel-generation 的 git 忽略规则

用户要求「除了原文，其它都应该 checkin，方便版本管理和查错，这不涉及版权」。此前 `.output/` 与 `worlds/*/novel.db` 被整体忽略：196 批模型原始响应、分片日志、生成章节、抽取出的知识都只在本机，改坏了无法回溯。而 `library/index.json`（7.4MB）本来就含全文，所谓版权防线并不成立。

收窄后只剩四类被忽略：`original.txt`（原始语料 5.9MB）、`novel.db-wal/-shm`（随进程变化）、`private/`（目录名即约定，且里面有原文摘录）、`.output/*.zip`（审核包可从已提交内容重新生成）。

两个技术点：① 根 `.gitignore` 的 `.output/` 会连工具目录一起排除，且**无法用下级 negation 救回**（git 不进入被排除的目录），必须改成 `/.output/`；② 数据库 28MB 里有 6MB 是反复 DELETE+INSERT 留下的空闲页，`VACUUM` 后 21.6MB，提交前一并做了。给 `*.db`/`*.zip` 标 `binary` 避免逐行 diff。

## 把写作状态拆到 story.db

用户问「meta 或不常变化的内容能否拆出来减少频繁写同一个 db」。实际写入分布正好相反：**不常变的是那 22MB 知识库（几周一次），频繁写的是几十 KB 的状态（每章）**。所以拆的是「小但常写」的一半。

`novel.db` 留 chunks / annotations / entities / story_analysis / story_graph_* / novel_*；`story.db` 放 story_state / characters / canon_facts / story_events / plot_threads / continuity_notes。各自 `user_version`，知识库仍是 4、状态库 1。

关键取舍：拆完 22MB 文件在写入路径上完全不出现（`openKnowledgeDatabase` 只在 `syncStoryState` 里打开一次做世界归属校验），但那次 open 也会让文件被 touch —— 实测确认 sha256 不变，因为打开时的 CREATE TABLE IF NOT EXISTS 与 `user_version` 判断都无写入。所以 `if(version<X)` / `if(!stored)` 这两个条件判断是必须的，否则每次打开都会写一页，白拆。

迁移：`fresh` 时把旧表行搬进 story.db 并在 novel.db DROP。`DatabaseSync` 无法跨文件事务，所以先提交目标库再删源表；失败只 warn，下次打开重试——不能让迁移失败阻塞写作。

副产物：`package-review` 有两个既有 bug 被这次运行暴露。① `edge_id AS from` 里 `from` 是保留字，整条 SQL 解析失败（story-graph 那次提交引进的，之后没人跑过这个脚本）；② 语料指纹变更后缓存目录不存在，`readdir` 直接 ENOENT，现在降级为「只有请求体」并标 `cacheAvailable=false`。

测试 124（新增「写作状态写入不触碰知识库」与「旧表迁移后删除」两条）。提交 `48109fda`，推送时 github.com 443 超时，重试也失败，本地待推。

## 人物「近重复」是误判，真正要做的是合并

上一节说「合并时缺一轮去重」。实测推翻了这个判断：李阎 193 条性格、194 条矛盾、380 条走向，两两 bigram Jaccard 相似度全部低于 0.6，阈值降到 0.6 也一条去不掉。原因是每批只看几章，同一个人被重新描述一次——**不是重复，是时间序列**。

改成合并：`character-profile.ts` 按章节顺序采样（首尾各 1/4 + 中间等距，避免只留前几卷），交给模型合成一份档案（画像 / 阶段 / 性格 / 矛盾 / 走向），写进 `novel_character_profiles`（schema v5），原始观察保留作证据。28 人已生成；李阎 964 条观察 → 244 字画像 + 5 段阶段 + 6 性格 + 6 矛盾 + 5 走向。

三个坑：
1. **观察太少会编**。天保仔 0 条、太岁 0 条，只有名字和身份，模型照样能写出「画像」。加 `MIN_OBSERVATIONS=4` 直接跳过，并清掉历史档案（否则旧档案会一直留着）。
2. **输出会被截断**。丹娘 51 条观察一次写不完，返回的 JSON 不完整。失败后减半采样再问一次，第二次成功。
3. **缓存键要含采样内容**，否则调整采样口径后仍命中旧档案。

`writing-brief` 与 `story-kb --type characters` 优先用合并档案，没有才退回 `role`。审核包里人物示例带 `profile` 字段，`arrayCounts` 仍保留原始体量。
