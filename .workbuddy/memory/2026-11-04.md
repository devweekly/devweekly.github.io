# 2026-11-04

## 文章页移动端「正文只占左侧 60%」的修复

**症状**：用户手机截图里正文列只占屏宽约 60%，右侧一大片背景留白，导航行里搜索图标单独换行居中。

**归因过程**（截图是 854×1658 = DPR 2 × 390 或 427 CSS 宽）：

- 用 iframe 精确控制视口宽度 + `--dump-dom` 把测量结果写进 `<pre>` 读回来，比 `--window-size` 可靠
  （headless 的 `--window-size` 不等于布局视口，直接截图会被裁切，误导判断）。
- 关键量：用户截图正文列 ≈ 238 CSS px，h1「Weight-Space」正好折行；本地 427 视口下 `article` = 395。
  238 / 395 = 0.6 —— 整页被等比缩到 60%，不是容器变窄。
- 原因：`.prose table` 的 min-content 宽度 389 > 手机正文列（320/360/375 下是 328/343/358），
  表格把 `article → main → document` 一路撑到 405。**iOS Safari 对此会 shrink-to-fit，整页缩放**，
  页面顶部（标题、摘要）也就只剩左侧一条，右侧空白。
- 参考数：`DIV.table-wrap cw=358 sw=389 over=31`、`HTML cw=390 sw=405`。

**改法**（三处，均已 push）：

1. `astro.config.ts` 加 `rehypeWrapTables()`：所有 Markdown 表格包一层 `<div class="table-wrap">`。
   不用 `display:block` 那套 table hack，保留原表格布局。
2. `src/styles/base.css`：
   - `.prose .table-wrap { overflow-x: auto; max-width: 100%; overscroll-behavior-x: contain }`
   - `.prose .table-wrap > table { min-width: 100% }`（窄表也占满列宽，视觉一致）
   - `.prose { overflow-wrap: break-word }`（长 URL / 英文词不撑宽正文列）
   - `body { overflow-x: clip }`（兜底：任何越界都不再触发移动端整页缩放）
3. `Header.astro`：移动端 `nav ul` 由 `justify-center gap-x-4` 改 `justify-between gap-x-1`，
   `nav ul li a` 的 `px-4` → `px-2`。5 项（Posts/Tags/About/Note/搜索）在 375/390 能排一行，
   不再让搜索图标单独换行居中、也不再多出一行死白。

**不要用的做法**：`th/td { overflow-wrap: anywhere }` —— 它参与 min-content 计算，确实能让表格收进列宽，
但会把 `Interference` 切成 `Interferenc|e`。改用默认的 `break-word`：宽表在 `.table-wrap` 内部横向滚动
（16 张表里只有 1 张需要滚 31px），不毁词。

**验证口径**（可作为以后移动端改动的回归检查）：

```text
iframe 宽度 = 320 / 360 / 375 / 390 / 414 / 427，读 documentElement.scrollWidth
要求 scrollWidth == clientWidth（隐藏滚动条后）
```

实测：weight-space 那篇 6 个宽度全等；再抽 9 个页面（含 52/45/38/29/25 张表的四篇）在 390 下全部相等。
桌面 1280：`article` = 832，16 张表均 832 fit，无回归。

**环境坑**：
- `pnpm dev` / `pnpm build` 会被 safe-delete shim 拦住（`node_modules/.vite`、`dist/.prerender` 文件数超阈值）。
  用 `mv node_modules/.vite /tmp/...` 代替 `rm -rf`。build 最后一步清理 `dist/.prerender` 仍会报错，
  但页面已全部生成，产物可用。
- `markdown.rehypePlugins` 在 Astro 7.3 有 deprecation 警告，仍生效。

**顺带发现（未改）**：桌面 1280 下 logo 被 `nav { w-full }` 挤成两行（「开发者周报 Builder / Weekly」），
`.logo` 的 `whitespace-normal` 是既有设置，属既有问题，与本次移动端修复无关。
