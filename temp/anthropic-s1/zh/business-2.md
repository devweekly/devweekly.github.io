过去，当本公司推出能力显著提升且单任务成本更低的新模型版本时，本公司通常看到客户扩大对本公司智能服务的使用。例如，本公司于 2025 年 11 月推出 Opus 4.5，其能力较前代 Opus 4.1 更强，价格与单任务成本更低。在该版本发布之后，本公司的季度环比总收入增长率从截至 2025 年 12 月 31 日的三个月的 48% 加速至截至 2026 年 3 月 31 日的三个月的 132%。这一增长反映了若干因素的共同作用，包括更低的价格与更强的能力开启了新的用例、新产品的出现，以及客户采用的扩大。此后，本公司于 2026 年 9 月推出 Opus 5.5，相较此前可用的模型，其能力显著提升且单任务成本更低，此后许多客户已从较旧模型迁移至该版本。

## Claude 模型系列

Claude 模型系列目前由四个模型类别组成：Mythos（包含 Fable）、Opus、Sonnet 与 Haiku。本公司的模型类别可单独用于某些任务，也可相互组合使用。它们提供广泛的灵活性，以便为每种用例选择理想的性能、成本与速度。所有模型均支持文本、代码与多模态输入。

- *Mythos（包含 Fable）*。本公司能力最强的模型类别，在各领域提供前沿性能，并解决 AI 此前无法可靠处理的问题，尤其是在编码与长时间运行的智能体任务中。鉴于其在软件漏洞发现与生物学等敏感领域的先进能力，本公司以两种不同配置部署这一底层模型。Fable 已全面可用，并在本公司的生产安全保障下运行，这些保障会阻止或限制某些敏感主题上的表现，包括将请求路由至能力较弱的 Claude 模型。Mythos 在经审核的组织与个人开展网络安全与生命科学工作时所用的、经过校准的安全保障下运行，并通过本公司的可信访问计划（包括网络验证计划）提供。本公司于 2026 年 4 月通过 Project Glasswing 以 Claude Mythos Preview 的形式首次提供该类别，于 2026 年 6 月使 Fable 5 全面可用并向 Project Glasswing 参与者提供 Mythos 5，并于 2026 年 9 月发布 Mythos 5.1 与 Fable 5.1。
- *Opus。* 本公司用于推理密集型任务的强大主力模型类别。本公司最新的 Opus 版本 Claude Opus 5.5 旨在成为企业的日常主力，驱动端到端运行项目的智能体，并在智能体化编码、计算机使用与知识工作方面提升能力。Opus 模型在关键行业基准测试中一贯位居领先模型之列。
- *Sonnet。* 本公司用于日常任务的多用途模型类别，为最广泛的一类通用用例提供性能、成本与速度之间的平衡，包括多智能体编排设置中的高频次子智能体。
- *Haiku。* 本公司成本最低、速度最快的模型类别。Haiku 模型专为高频次工作负载设计，例如客户服务智能体与大规模文档处理。
## Claude 平台

客户选择 Claude 的原因不止于模型。Claude 平台使开发者与企业能够在其具有高可靠性、安全性与可用性的基础设施上构建、管理并部署智能体化 AI 应用程序。

*平台功能*

平台功能使开发者能够定制其对 Claude 的使用，包括：

- *扩展思考（Extended Thinking）*。Claude 可在生成最终回复之前进行额外的内部推理，逐步处理复杂的多步问题，以提升分析、数学与编码等任务上的回复质量。
- *自适应思考（Adaptive Thinking）*。Claude 会自动校准某一请求是否需要扩展推理以及应投入多少推理，从而使开发者无需逐请求配置推理层级即可获得扩展推理的益处。
- *投入度控制（Effort Controls）*。开发者可为每个请求指定投入度水平，以引导 Claude 投入的推理量，从而在回复质量与成本、延迟之间取得平衡。
- *工具使用（Tool Use）*。Claude 可在整个对话中原生调用外部函数与 API，并支持并行执行以及工具调用之间的交错思考。搜索工具按需仅加载给定任务所需的工具，相较预先加载完整工具库，可减少 token 开销。
- *长上下文（Long Context）*。Claude 支持大上下文窗口，并在输入增长时仍保持强劲性能，这意味着开发者可在单个请求中包含整个代码库、大量文档集合或较长的智能体历史记录。
- *结构化输出（Structured Outputs）*。开发者可将 Claude 的回复约束为指定模式，例如有效的 JSON（JavaScript Object Notation），从而使结果能够与下游系统及应用程序代码可靠集成，减少额外的解析或校验。
- *代码执行（Code Execution）*。一个沙箱化执行环境，Claude 可在智能体循环中在其中编写、运行并迭代代码，这是数据分析与自动化工作流的基础。该环境使 Claude 能够更高效地调用工具、处理大量数据，并运行打包在 Agent Skills 中的脚本。
- *网页搜索（Web Search）*。一项原生工具，使 Claude 能够访问实时网页信息，从而在生产应用程序中提供有依据、可标注引用的回复。
- *文件 API（Files API）。* 使开发者能够一次上传文档并在多个会话中引用，简化依赖持久化文档的工作流。
*上下文管理*

开发者可使用上下文基础构件将上下文连接至 Claude，以供其智能体与应用程序使用。

- *模型上下文协议（Model Context Protocol）。* MCP 是本公司于 2024 年 11 月推出、并于 2025 年 12 月捐赠给 Linux 基金会旗下 Agentic AI Foundation 的开放标准。MCP 定义了一套通用接口，Claude 以及其他 AI 工具可通过该接口连接企业数据源、工具与工作流。Claude 平台的原生 MCP 连接器自动处理连接管理、工具发现与错误处理。
- *Agent Skills。* 一个模块化框架，使组织能够将可重复的任务、工作流与领域专业知识编码为可复用的包（即 skills），由 Claude 按需加载。本公司为 Word、Excel、PowerPoint 与 PDF 等常见格式提供预构建的 skills，而自定义 skills 可涵盖从工程标准与监管流程到专有工具链的各类内容。这些 skills 将机构知识转化为智能体能力。• *模型硬件标准（Model Hardware Standard）*。目前处于研究预览阶段，本公司的模型硬件标准使 AI 智能体能够发现、理解并安全操作实验室与制造设备，例如显微镜、液体处理仪与现成的机械臂。本公司的模型硬件标准与模型无关，并使任何智能体运行框架都能通过 MCP 等标准协议访问具有可编程接口的设备。
*基础设施*

Claude 平台为企业级智能体化工作负载提供高可靠性与可用性。在 Claude 之上构建的客户需要模型在其运营的任何地点都能可靠地提供服务，需要模型能够以规模化与高速度高效运行，还需要能够使模型自主工作的工具。本公司运营该基础设施，使客户无需自行构建与维护。

- *可用性*。Claude 平台可直接从 Anthropic 获取，也可通过主要云服务提供商（包括 AWS、GCP 与 Azure）获取。功能可用性因部署方式而异。
- *成本、速度与规模*。开发者可调整 Claude 的运行方式，以适应每种工作负载的性能与经济性：
- *提示缓存（Prompt Caching）*。大量重复使用的提示组成部分可被缓存最长一小时，相较于在不使用缓存的情况下处理相同请求，可使长提示的成本降低最高约 97%、延迟降低约 60%。
- *批处理（Batch Processing）*。以更低成本实现高频次异步处理。
- *快速模式（Fast Mode）*。为对延迟敏感且速度至关重要的交互式应用程序提供更低延迟的回复。
*智能体运行框架*

模型本身并不等同于智能体。在生产环境中可靠地运行智能体具有挑战性，因为智能体必须能够承受崩溃与中断、以范围受限且可审计的凭证对系统执行操作，并在可变的工作负载下扩展。自主运行需要一个运行框架，它提供模型进行规划、调用工具、验证其工作并安全自主完成任务所需的安全环境、凭证、记忆与编排循环。构建并运营该基础设施是一项专业化的持续性工作，直到不久之前，每位客户都必须自行承担。本公司在 Claude 平台上提供两种运行框架的方式：

- *Agent SDK。* 该解决方案将驱动 Claude Code 的同一生产级运行框架提供给所有开发者，使其可在自有算力上运行。它内置上下文管理、会话处理、多智能体协调与提示优化，使客户能够以相较其他方式所需时间的一小部分，在其自有基础设施上构建并运行复杂的智能体。
- *Claude 托管智能体（Claude Managed Agents）。* 一种开箱即用的解决方案，本公司代表客户在 Anthropic 管理的算力上运营该运行框架。本公司托管沙箱、存储凭证、维护记忆并运行智能体循环；客户则定义其智能体的任务、工具与护栏。当有新模型可用时，客户无需重建其智能体循环。
## 直接应用程序与集成

本公司的平台基础构件与模型是所有产品的基础，并支持广泛的用例，从编码智能体到生命科学、金融、安全等领域的专业化产品。结合本公司对模型当前与未来能力的深入理解，这一基础使本公司能够快速交付产品，为众多用户类型与工作流释放价值。

- *Claude Code。* 一款编码智能体，以终端工具、桌面应用、网页界面与移动应用的形式提供，并与 GitHub 及主流 IDE（集成开发环境）原生集成。Claude Code 在大型代码库中处理多步软件开发任务——规划、编写、编辑、测试、调试与提交代码——并能维持持续的上下文，同时支持并行的智能体会话，使单个开发者能够并行推进多个任务。• *Claude Cowork。* 一款桌面、网页与移动端的知识工作智能体，构建于 Claude Code 的智能体化架构之上。用户以自然语言描述任务，Claude 将其拆解为步骤，并在本地文件、已连接的应用程序、Chrome 以及桌面本身之中完成这些步骤，在没有集成的情况下通过原生应用程序进行点击与输入。它返回完成的文档、电子表格、演示文稿与整理好的文件夹，且无需终端或代码。一个开源插件系统使用户能够安装或构建捆绑 skills、数据连接器与工作流的包。
- *Claude.ai。* 本公司的旗舰对话式产品，在桌面、网页与移动端提供。Claude.ai 是通往 Claude 最广泛的入口，面向企业、团队与个人提供，可访问本公司 Claude 模型系列，并支持文件上传、用于跨对话持久上下文的项目、记忆、网页搜索，以及用于实时渲染代码与文档的 artifacts。Claude.ai 为企业采用带来漏斗顶端的获客。2026 年 9 月，本公司开始将 Claude Cowork 与 Claude.ai 合并为一个统一应用程序，使任何请求都会借助 Claude Cowork 的能力，自动以适当的工具处理。
- *Claude Security。* 一款防御性网络安全产品，以公开测试版向 Claude Enterprise 客户提供，将前沿漏洞检测与修补能力交到安全团队手中。Claude Security 像安全研究员一样对代码进行推理，追踪数据流并检视各组件在整个代码库中的交互方式，以发现基于模式的扫描器可能遗漏的复杂、依赖上下文的漏洞。每项发现均附带置信度评级、严重性评估与复现步骤。用户可直接进入 Claude Code 审阅并应用建议的补丁，从而压缩从扫描到修复的时间。
- *Claude Tag*。一款协作式智能体，在 Slack 等生产力工具中与团队并肩工作，用户可在任意频道或会话中将 Claude 标记进来，并以自然语言委派工作。借助周围对话、企业软件工具、共享文档以及按频道范围的记忆所提供的上下文，Claude 直接在会话中返回答案、草稿、分析与拉取请求，作为一个能判断何时主动加入对话的环境型队友运作。Claude Tag 将 Claude 带入团队已经协作的多方工作流，把采用从个人扩展至整个组织。

本公司的数据中心策略

历史上，本公司以固定期限协议购买算力。随着本公司算力需求的扩大，本公司已转向一种混合模式：除将算力作为云服务购买外，本公司还直接采购专用 AI 加速器，并按本公司的规格在由他人代表本公司租赁与运营的专用数据中心设施中运行这些硬件。本公司将这一额外算力来源称为 Anthropic Direct。这一转变部分源于本公司算力需求的规模，以及直接租赁与托管基础设施在长期经济性方面的潜在优势。本公司的首个数据中心设施已于今年投入运营。

Anthropic Direct 还使本公司能够将对数据中心容量的承诺与对部署于其中的 AI 加速器的承诺相分离。由于数据中心需要更长的交付周期，但在总算力成本中所占比例较小，这一方式使本公司能够提前锁定数据中心容量，同时将更大规模的加速器投资推迟至本公司的具体算力需求更为确定之时。

本公司的数据中心基础设施策略包括若干合同安排，这些安排合在一起构成一种新的算力来源，用以补充本公司从云服务提供商处采购的容量。此类安排包括以下各项：

- *算力基础设施设备。* 本公司通过主设备租赁协议采购专用 AI 加速器及相关组件（包括 CPU 与高带宽内存），其中包括 2026 年租赁安排，据此本公司获得此类硬件，以部署在由他人代表本公司运营的专用数据中心设施中。有关这些租赁条款的更多信息，详见标题为“管理层对财务状况与经营成果的讨论与分析——流动性与资本资源——合同义务——基础设施设备租赁”的章节。
- *数据中心。* 在本公司的某些数据中心基础设施安排中，第三方合作伙伴采购底层房地产、电力与数据中心设施，而本公司租赁这些设施中的容量，并与专业第三方运营商签订合同以进行持续的设施管理。例如，本公司与 Fluidstack USA I Inc.（“Fluidstack”）签订了托管与服务协议，由 Fluidstack 向本公司提供数据中心开发与运营服务。本公司还直接签署了数据中心租约，并预计随时间的推移将越来越多地采取这一方式。为锁定某些需要在部署之前进行大额资本承诺的数据中心开发项目，本公司在某些情况下已依赖、并预计将继续依赖与融资方或合作伙伴的安排，由其为租赁义务提供担保，以支持预计将承载该合作伙伴芯片或计算基础设施的数据中心容量的开发。本公司未来通过这些安排扩展算力与基础设施容量的能力，可能取决于有限数量的云服务提供商、合作伙伴与融资方是否持续愿意并有能力订立并履行这些安排。
- *电力。* 电力采购需要与公用事业提供商另行安排，或在某些情况下开发表后发电容量，直接向设施供电而非通过更广泛的电网供电。为数据中心项目锁定充足的电力容量，无论是通过并网安排还是表后安排，通常都需要较长的交付周期，并须在设施投入运营之前很早就作出重大财务承诺。
本公司的数据中心基础设施项目目前主要位于美国。随着本公司持续扩大全球客户基础与研究运营，本公司正在国际上寻求更多数据中心容量，以支持本公司全系列工作负载。

## Claude 如何为客户创造价值

客户通过三种主要方式从 Claude 中获得价值：更高生产率的员工、更快的流程，以及产品中嵌入的智能。这些成果是同一智能的不同表现形式，各自依托相同的模型与基础构件。

*更高生产率的员工。* 采用往往从这里开始。个人体验到前沿 AI 模型能够对其自身产出产生的影响——例如，数小时的财务分析或代码审阅在数分钟内完成——这种信念便从首位用户传播至其团队，并从一个团队传播至整个公司。这在软件开发中的 Claude Code 上得到体现；Claude Cowork 则为更广泛的知识工作者带来同样的效果。本公司的 Claude Enterprise 套餐提供治理、安全与管理能力，以支持 Claude 在组织范围内的采用。

*更快的流程。* 随着采用加深，Claude 不再只是员工咨询的对象，而开始成为组织赖以运行的依托。随着组织将更多工作流（其数据、系统、惯例与既往工作）编码进 Claude，该平台对其而言变得更有价值。Claude 能够借助这些累积的上下文，建议下一个值得自动化的工作流，从而减少每次后续部署所需的投入。

*嵌入式智能。* 在最深层次上，Claude 从运营优势转变为商业优势。产品团队在 Claude 平台上构建，将前沿 AI 嵌入其自有产品，包括面向客户的智能体、AI 原生功能，以及此前在缺乏 AI 能力时无法成立的整条新产品线。Claude 既是组织使用的工具，也是其向自身客户交付价值的一项要素。

在这三个维度上，相当一部分扩展仅需极少甚至无需新的部署。Claude 模型的每个新版本均旨在改善既有用例的表现：员工产出更高质量的工作，已编码的流程以更高的准确性与可靠性运行，嵌入式产品为最终用户交付更多价值。因此，客户能够增加使用量、采用更高层级的订阅套餐，并将更多工作流引入平台，而无需新的销售周期或采购决策。

尽管采用速度如此之快，本公司相信本公司仍处于渗透前沿 AI 机遇的最早期阶段。与 Claude 当前所能承担的工作范围、以及本公司相信 Claude 未来所能承担的工作范围相比，当今使用 Claude 的大多数企业仅将其部署在少数团队与用例中。本公司相信，全球大多数知识工作者尚未使用过前沿 AI。随着 Claude 模型的每个新版本在能力上不断进步，平台上可成立的任务与工作流范围持续扩大。由于本公司运营该平台并提供应用程序，模型进步会同时通过多个渠道触达本公司客户。
